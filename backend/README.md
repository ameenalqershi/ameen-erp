# Ameen ERP — Backend

نواة ASP.NET Core APIs تستهدف **.NET 10** وEF Core وSQL Server. هذه دفعة تنفيذ للأستاذ العام والتهيئة؛ باقي أقسام ERP في التحليل لم تُنفّذ بعد. راجع [المطابقة وحدود المرحلة](../docs/backend/traceability.md) قبل إضافة أي وظيفة.

## البناء والاختبار

المتطلبات: SDK .NET 10، اتصال NuGet، وSQL Server 2022+ عند التشغيل أو اختبارات التكامل.

```bash
cd backend
dotnet restore Ameen.Erp.sln --locked-mode
dotnet build Ameen.Erp.sln -c Release --no-restore
dotnet tests/Ameen.Erp.Tests/bin/Release/net10.0/Ameen.Erp.Tests.dll
```

الاختبارات برنامج تنفيذي يعيد رمز خروج غير صفري عند الفشل؛ `dotnet test` وحده لا يشغّل هذه الحزمة. لتشغيل اختبارات SQL، عرّف `AMEEN_TEST_SQL_CONNECTION` لاتصال **خادم اختبار** بصلاحية إنشاء قواعد مؤقتة، ثم:

```bash
dotnet tests/Ameen.Erp.Tests/bin/Release/net10.0/Ameen.Erp.Tests.dll --sql
```

تنشئ الحزمة قاعدة `AmeenErp_Test_<guid>` وتطبّق عليها سكربت الإصدار مرتين، وتختبر التزامن والتراجع والعكس ومرشحات التقارير والمفاتيح الأجنبية ودور تشغيل SQL محدودًا، ثم تحذف القاعدة التي أنشأتها. تتضمن الحزمة تشغيل مضيف API الفعلي على HTTPS مع جهة OIDC مؤقتة واختبار JWT وOpenAPI. لا تستخدم اتصال الإنتاج. غياب متغير الاتصال مع `--sql` يفشل الاختبار ولا يتجاوزه بصمت.

لإعادة التحقق كاملًا وإنتاج سجل نتائج وعقد OpenAPI داخل `backend/.artifacts`:

```bash
python3 scripts/verify.py --sql
```

يشترط الأمر متغير الاتصال نفسه. تشغيله دون `--sql` يختبر النواة ومضيف HTTP الاختباري فقط. يدعم `--dotnet /path/to/dotnet` لتحديد SDK خارج PATH. ملف `global.json` يحدد عائلة SDK 10، وملفات `packages.lock.json` تثبت التبعيات؛ فحص ثغرات NuGet مفعّل للتبعيات المباشرة والمتعدية.

## إعداد قاعدة البيانات

1. أنشئ قاعدة فارغة باسم `AmeenErp` باستخدام هوية إدارة منفصلة.
2. طبّق سكربتات [database](database) المرقمة من 001 إلى 011 بالترتيب، ثم سكربت runtime-role.sql. السكربتات ذرية وقابلة لإعادة التطبيق وتسجل الإصدار في `__AmeenSchemaVersions`. عند ترقية قاعدة موجودة طبّق فقط الأرقام التالية لإصدارها بالترتيب؛ الإصدار الحالي 11. لا يوجد `EnsureCreated` أو ترحيل تلقائي عند بدء API.
3. طبّق أو أعد تطبيق [database/runtime-role.sql](database/runtime-role.sql)، وأنشئ مستخدم اتصال خاصًا بالتطبيق وألحقه بدور `ameen_runtime`. احتفظ بأسرار الاتصال خارج Git.
4. استخدم نسخًا احتياطية واختبار استعادة قبل أية ترقية لاحقة. شاشة النسخ والاستعادة SYS15 لم تُنفّذ.

السكربت الأول وُلد من نموذج EF Core 10، وطُبق فعليًا في اختبارات SQL Server محلية. دور التشغيل فُحص بحفظ أمر حقيقي ومحاولة تعديل سجل تدقيق مرفوضة. نتائج البيئة والإصدارات في [سجل التحقق](../docs/backend/validation.md).

## إعداد الهوية وتشغيل API

API تعتمد جهة هوية OIDC عبر HTTPS؛ إدارة كلمات المرور وMFA واسترجاع الحساب لدى تلك الجهة. لا توجد كلمات مرور افتراضية أو مسار تجاوز للمصادقة.

- `ConnectionStrings__Erp`: اتصال SQL Server مشفر، بمستخدم التطبيق.
- `Authentication__Authority`: عنوان issuer لدى جهة الهوية عبر HTTPS.
- `Authentication__Audience`: audience مخصص لهذه الـAPI.
- `AllowedHosts`: أسماء النطاقات الفعلية.
- `Cors__Origins__0` وما بعده: عناوين واجهة الويب المسموحة؛ القائمة الفارغة لا تسمح بطلبات CORS. الإنتاج يتطلب HTTPS وعناوين صريحة.
- `ASPNETCORE_URLS`: عنوان HTTPS للتشغيل؛ استخدم شهادة تطوير محلية أو شهادة خدمة مناسبة.

القالب [.env.example](.env.example) للتوثيق؛ التطبيق لا يقرأ ملفات dotenv تلقائيًا. عرّف القيم في البيئة أو مدير أسرار التشغيل. محليًا يمكن إعداد شهادة عبر `dotnet dev-certs https`.

```bash
dotnet run --project src/Ameen.Erp.Api
```

المسارات: `/health/live` للفحص الحي، و`/health/ready` للفحص الموثّق لاتصال قاعدة البيانات وإصدار المخطط 11 وجدول الشركات، و`/openapi/v1.json` لوصف API الموثّق. سجل الإصدار شرط جاهزية، وليس تدقيقًا مستقلًا لكل عمود إذا عُدلت قاعدة البيانات خارج سكربتات المشروع.

توكن المستخدم يجب أن يتضمن `sub` ثابتًا. لإنشاء الشركة فقط، يُمنح المستخدم المختص claim من نوع `roles` بقيمة `erp.platform-admin` من جهة الهوية. صلاحيات الشركة والفروع تُقرأ من قاعدة ERP في كل عملية. المسؤول العام لا يحصل على صلاحيات مالية ضمنية. بعد إنشاء الشركة، تُمنح عضويات لمُدخل قيود ومُعتمد مستقل وفق [دليل العقود](../docs/backend/api.md).

يمكن بناء الحاوية من هذا المجلد بـ`docker build -t ameen-erp-api .`. تشغّل الحاوية هوية غير root، وتتطلب شهادة HTTPS مركّبة ومتغيرات الاتصال والهوية. لا توجد حاوية هوية أو قاعدة إنتاج جاهزة ضمن المشروع. النشر خلف reverse proxy يحتاج تحديد الوكلاء الموثوقين والشهادات وفق بيئة النشر؛ لم يُفعّل قبول forwarded headers من أي مصدر.

## التحقق وملفات العقود

أصبح المشروع يعتمد .NET 10 في البناء والتشغيل والاختبار. أُنجز تحقق محلي فعلي على SDK 10 وSQL Server، مع اختبار اكتشاف OIDC وJWKS والتحقق من التوقيع والعمر والـissuer والـaudience. جهة الهوية المستخدمة مؤقتة للاختبار؛ إعداد جهة هوية المستخدمين في النشر ما زال مطلوبًا.

عقد الـAPI المولد محفوظ في [openapi/v1.json](openapi/v1.json)، ونتائج الفحص في [سجل التحقق](../docs/backend/validation.md). يعاد توليد العقد عبر حزمة التحقق عند تفعيل `--sql`. [GitHub Actions](../.github/workflows/backend.yml) مجهّز لتشغيل الحزمة ورفع الأدلة؛ أصبح المستودع الخاص موصولًا؛ نتيجة CI تراجع في صفحة Actions ولا تستنتج من النجاح المحلي.

دورة القوالب الدورية وصلاحياتها وترقيتها موثقة في [GL04](../docs/backend/recurring-journals.md). لا تُولّد القوالب إلا مسودات، وتبقى الموافقة والترحيل مستقلين.

يمكن استخراج تعريف النموذج دون اتصال بقاعدة عبر `dotnet <path-to-Ameen.Erp.Api.dll> --schema`. هذا أمر مراجعة فقط ولا يطبّق تغييرات على البيانات.

بطاقة دليل الحسابات وطبيعة الرصيد وقواعد التعديل والاستخدام موثقة في [عقد GL01](../docs/backend/accounts.md). طلب إنشاء الحساب يتطلب `normalBalance` صراحة؛ لا يفرض تصنيف الحساب طبيعته، لدعم الحسابات المقابلة.

تفاصيل إدارة العملات وشجرة المراكز وصلاحياتها وترقيتي 004 و005 في [SYS04 وCOST01](../docs/backend/currencies-and-cost-centers.md).

عقد SYS01 الإلزامي الجديد، وضوابط تعطيل الشركة وترقية الشركات القديمة في [بطاقة الشركة](../docs/backend/companies.md).

حقول الفرع الإلزامية الجديدة وشجرة SYS02 وترقية 007 في [الفروع والإدارات](../docs/backend/branches.md).

يدعم SYS03 فترات مالية صريحة عند إنشاء السنة؛ تفاصيل [التقويم المالي](../docs/backend/fiscal-calendar.md). لا تتطلب هذه الإضافة ترقية بعد الإصدار 007.

استعلامات أسعار الصرف ومعاينة موانع إقفال الأستاذ في [SYS05 وGL11](../docs/backend/rates-and-close-preview.md)، دون ترقية SQL جديدة.

أساس المخزون INV03 ودليل الوحدات وترقية 008 في [وحدات القياس](../docs/backend/units.md).

شجرة مجموعات الأصناف وربط الحسابات وترقية 009 في [INV02](../docs/backend/item-groups.md).

بطاقة الصنف ووحداته وباركوده والتحويل الدقيق وترقية 010 في [INV04](../docs/backend/items.md).

ابدأ استئناف العمل من [سجل التقدم والتسليم](../docs/backend/PROGRESS.md). بعد تحديث المصفوفات ونتائج التحقق، شغّل `python3 scripts/progress.py` ثم `python3 scripts/progress.py --check` من مجلد backend؛ CI يفحص تطابق الجداول مع الأدلة المسجلة.

بطاقة المخزن ومواقعه وحماية مراجع الحساب والفرع وترقية 011 موثقة في [INV01](../docs/backend/warehouses.md).

[تنظيم الملفات حسب الوحدات والمسؤوليات](../docs/backend/code-organization.md): مسارات API منفصلة، ملف لكل كيان وعقد، Features لخدمات التطبيق وPersistence/Configurations لتهيئة EF.

تسجل `ApplicationServiceRegistration.AddErpApplication` خدمات الميزات المستقلة بنطاق Scoped؛ لا يوجد ErpService جامع في الإنتاج. تعمل الخدمات المتعاونة على مخزن ومعاملة وDbContext الطلب نفسه.

البحث في سجل التدقيق SYS14 ومرشحات UTC والمستخدم والحدث والمرجع وتفاصيل الحدث موثق في [سجل التدقيق](../docs/backend/audit-log.md).
