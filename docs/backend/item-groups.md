# مجموعات الأصناف INV02

تنفذ هذه الدفعة شجرة المجموعات وربطها بحسابات المبيعات والمخزون والتكلفة، مع البطاقة ثنائية اللغة والملاحظات والحالة والإصدار العددي والتدقيق. أضيفت بطاقات الأصناف لاحقًا في INV04، وتبقى الحركات ورمز الضريبة الافتراضي غير منفذين؛ تبقى الشاشة جزئية. لا تورث حسابات الأب تلقائيًا، ولا توجد سياسة تسمح للصنف بتجاوز إعدادات المجموعة.

## العقد

جميع المسارات تحت `/api/v1/companies/{companyId}/item-groups` وتتطلب الهوية:

| المسار | السلوك والصلاحية |
|---|---|
| GET / | صفحات وبحث search/parentId/isActive/offset/limit؛ ledger.read |
| POST / | إنشاء؛ company.configure لكل الفروع |
| GET /{id} | بطاقة المجموعة؛ ledger.read |
| PUT /{id} | استبدال بيانات البطاقة مع expectedVersion وreason؛ company.configure لكل الفروع |
| POST /{id}/status | تفعيل أو تعطيل مع expectedVersion وisActive وreason؛ company.configure لكل الفروع |
| GET /{id}/audit-events | صفحات أحداث البطاقة؛ ledger.read وaudit.read لكل الفروع |

الكتابة تتطلب Idempotency-Key. الإنشاء والتعديل والحالة تحفظ البطاقة والتدقيق والإيصال معًا؛ إعادة الطلب لا تكرر الأثر. الرمز نص حتى 32 حرفًا وفريد داخل الشركة، ويحفظ الأصفار البادئة. الاسمان حتى 200 حرف والملاحظات حتى 2000. الحقول الاختيارية تقبل null، والتعديل يتطلب إرسالها صراحة حتى عند إزالتها. Revision يبدأ من 1؛ Version رمز التزامن التقني.

```json
{
  "code": "001",
  "name": "مجموعة تجريبية",
  "salesAccountId": "11111111-1111-1111-1111-111111111111",
  "parentId": null,
  "inventoryAccountId": null,
  "costAccountId": null,
  "englishName": "Example group",
  "notes": null
}
```

استبدل معرف الحساب بحساب موجود فعليًا. الحسابات تكون من الشركة نفسها، فعالة وقابلة للحركة. حساب المبيعات من الإيرادات، والمخزون من الأصول ورقابي لمنع الحركة اليدوية، والتكلفة من المصروفات. حساب المبيعات إلزامي؛ المخزون والتكلفة اختياريان في بطاقة المجموعة، ويشترطهما INV04 عند إنشاء صنف غير خدمي. هذا الربط لا ينشئ قيدًا ولا يمنح حساب المخزون مسار ترحيل آليًا جاهزًا.

## الشجرة وحماية الحسابات

الأب من الشركة نفسها وفعال؛ يمنع ربط المجموعة بنفسها أو بأحد أبنائها. تعطيل الأب يتطلب تعطيل الأبناء الفعالين، وتفعيل الابن يعيد التحقق من سلسلة آبائه وحساباته. الحساب المعطل لا يسمح بتفعيل مجموعة تشير إليه. يمكن تصحيح وصف مجموعة معطلة دون إجبار المستخدم على تفعيل حساباتها أولًا.

أضيفت المجموعات إلى مراجع استخدام الحسابات: تغيير البنية المالية للحساب أو أحد آبائه محجوب ما دامت المجموعة تشير إليه، حتى إن كانت معطلة. تعطيل الحساب محجوب عند ارتباطه بمجموعة فعالة؛ غيّر الرابط أو عطل المجموعة أولًا. التعديلات الوصفية للحساب تبقى متاحة. هذا الفحص متسلسل مع أوامر الشركة، فلا يتسابق تغيير الحساب مع إنشاء المجموعة.

`GET /api/v1/companies/{companyId}/accounts/{id}/item-groups` يعرض المجموعات المرتبطة مباشرة بالحساب مع الصفحات، ويتطلب قراءة لكل الفروع. `hasUsageInSubtree` في ملخص GL01 يشملها الآن؛ قائمة References القديمة تبقى مخصصة للقيود والقوالب ولا تستخدم معرف فرع وهميًا للمجموعة المشتركة للشركة. استخدم المسار الجديد لمراجع المجموعات.

ربط المجموعة أو أحد أبنائها بصنف يقفل رمزها وأبها وحساباتها، ويمنع الصنف الفعال تعطيل المجموعة. يشترط INV04 حسابي المخزون والتكلفة لغير الخدمة. تبقى سياسة الضريبة والتجاوز ودفتر المخزون غير منفذة؛ تفاصيل [INV04](items.md).

## الترقية والتحقق

طبّق السكربتات 001 إلى [009_item_groups.sql](../../backend/database/009_item_groups.sql) بالترتيب ثم runtime-role.sql. الإصدار المطلوب للجاهزية أصبح 9. الترقية تضيف جدولًا فارغًا وفهارس ومفاتيح مركبة للأب والحسابات، دون توليد مجموعات أو تغيير بيانات سابقة. لا توجد ترقية آلية عند بدء API.

تشمل [الاختبارات](../../backend/tests/Ameen.Erp.Tests/ItemGroupTests.cs) الدورة والتفعيل والحسابات والصلاحيات والإعادة والتراجع. يختبر [SQL](../../backend/tests/Ameen.Erp.Tests/ItemGroupSqlIntegration.cs) نقلين متزامنين لا يمكن أن ينشئا دورة، وفشل التدقيق والتراجع وإعادة المحاولة بدور التشغيل، وعزل حسابات الشركات. تشمل حزمة التحقق فشل ترقية DDL وإعادتها ومسارات HTTPS/JWT الفعلية.

## عرض الاستخدام INV02

- `GET /api/v1/companies/{companyId}/item-groups/{id}/usage`: هوية المجموعة وإصدارها `GroupVersion`، وعدد الأبناء المباشرين والفعالين وعموم الأحفاد (لا يشمل المجموعة نفسها)، وعدد الأصناف المباشرة والفعالة وكل أصناف الشجرة والفعالة منها.
- `GET /api/v1/companies/{companyId}/item-groups/{id}/items?includeDescendants=true&isActive=false&offset=0&limit=50`: أصناف المجموعة مع وحداتها؛ يشمل الفروع افتراضيًا. حذف `isActive` يعيد الفعالة والمعطلة معًا. `includeDescendants=false` يحصر المجموعة نفسها. الترتيب Code ثم Id، حجم الصفحة 1..200 والإزاحة 0..1000000.

كلا المسارين يتطلب `ledger.read` ونطاق جميع الفروع، كما في عرض الاستخدام العام للوحدات والحسابات؛ قراءة البطاقة العامة وحدها لا تمنح حق ملخص الاستخدام. الشركة تؤخذ من المسار والتحقق يسبق كشف مرجع المجموعة. لا تُستثنى الأصناف المعطلة من قفل البنية ولا المجموعات المعطلة من اجتياز الشجرة.

`StructureLocked` يعني وجود أي صنف مباشر أو ضمن الأحفاد؛ `HasDeactivationBlockers` يعني أصنافًا فعالة مباشرة أو مجموعات أبناء فعالة، وفق حارس التعطيل الحالي. استعمال المجموعة في صنف معطل يقفل بنيتها دون منع تعطيلها بحد ذاته. الأصناف في مجموعات غير تابعة لا تدخل الملخص. تستخدم قراءة الشجرة وحارس تعديلها نفس اجتياز الشجرة مع كشف الدورات.

هذه قراءة استرشادية وليست موافقة محجوزة للتعديل: لا يمنع GroupVersion تغير أبناء المجموعة أو الأصناف بعد القراءة، ولا تقدم الاستعلامات المتعددة لقطة SQL واحدة. يعاد فحص الموانع داخل معاملة أمر الكتابة. الملخص يقرأ مراجع الشجرة في التطبيق؛ لا ضمان أداء لشجرة أو دليل ضخم دون اختبار حمل. لا يحسب أرصدة أو تكلفة مخزون، ولا ينشئ قيدًا أو تدقيق كتابة أو إيصالًا.

اختبارات `ItemGroupUsageTests.cs` تغطي الفروع المتداخلة وعدم ازدواج العد والأصناف المعطلة والصفحات والعزل والصلاحيات وتوافق أسباب القفل مع أوامر التعديل والتعطيل. يمتد التحقق إلى SQL الحي وHTTPS/JWT. لا ترقية لقاعدة البيانات؛ المخطط يبقى 10.
