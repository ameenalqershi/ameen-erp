# SYS14 — البحث في سجل التدقيق

تستكمل هذه الدفعة مرشحات سجل التدقيق وتفاصيل الحدث، داخل خدمة AuditService المستقلة. مرجعها حقول SYS14-F03/F04/F09/F10 وغرض تتبع من فعل ماذا ومتى. تبقى الشاشة جزئية: لا مرشح شاشة أو رقم مستند أو تصدير أو نطاق فرع مستقل، ولا يُحوّل resourceId إلى رقم مستند.

## الواجهات

`GET /api/v1/companies/{companyId}/audit-events`

| المعامل | الدلالة |
|---|---|
| from | يوم البداية بصيغة yyyy-MM-dd، من 00:00:00 UTC شاملًا |
| to | يوم النهاية شاملًا كامل اليوم UTC؛ الاستعلام أقل من بداية اليوم التالي |
| actorId | هوية OIDC sub المحفوظة تاريخيًا، حتى لو لم تعد هناك عضوية فعالة |
| action | مفتاح الحدث المحفوظ، مثل warehouse.created أو journal.posted؛ تطابق تام، لا بحث جزئي |
| resourceId | UUID مرجع الحدث؛ لا يشترط بقاء المرجع فعالًا أو متاحًا في بطاقة تشغيل |
| offset / limit | الإزاحة 0..1000000، حجم الصفحة 1..200؛ الافتراضي 0 و50 |

تُجمع المرشحات بـAND قبل حساب العدد والصفحات، وتُرتب الأحداث بالأحدث ثم Id لكسر تعادل التوقيت. حذف مرشح يعني عدم تقييده. التاريخ اختياري للحفاظ على العملاء الحاليين؛ لذلك F03/F04 جزئيان قياسًا بإلزامهما في شاشة التحليل. يسمح بتاريخ نهاية 9999-12-31 دون تجاوز مجال التاريخ، وبتحديد طرف واحد من الفترة. رفض الصيغة أو انعكاس الفترة يرجع 422 وفق عقد أخطاء الأعمال الحالي.

actorId وaction نصان غير فارغين بعد Trim بحد 200 و100؛ المقارنة حساسة للحالة ولا تقبل مطابقة سجل يحتوي مسافة لاحقة زائدة. استعلام SQL يطبق BIN2 وDataLength، دون الاعتماد على collation الافتراضي للقاعدة. الأسماء والقيم التاريخية لا تُحذف من البحث عند تعطيل المستخدم. مرجع المستخدم في التحليل ليس مفهرس هوية إنتاجيًا معتمدًا بعد، ونوع الحدث هنا مفتاح تاريخي وليس قائمة سياسة شاشة نهائية؛ كلاهما معلن partial في المصفوفة. مرشح غير معروف يعيد صفحة فارغة ولا يعد خطأ بحد ذاته.

`GET /api/v1/companies/{companyId}/audit-events/{id}` يعيد الحدث نفسه: الشركة، المستخدم، نوع الحدث، المرجع، التوقيت وDetails. لا ينفذ إجراء على المرجع ولا يمنح صلاحية تعديل السجل. التفاصيل المحفوظة كما هي؛ لا تُشتق قيم قبل/بعد جديدة من الحالة الحالية للبطاقة.

## الصلاحيات والحدود

كلا المسارين يتطلب `audit.read` ونطاق جميع الفروع في الشركة. لا يمكن استعمال UUID حدث من شركة أخرى، ولا يتم كشف تفاصيله قبل التفويض. القراءة لا تضيف حدث تدقيق أو إيصال أمر، لذلك تدقيق عمليات القراءة يظل متبقيًا صريحًا. لا يُستخدم هذا المسار كواجهة أسرار؛ الأحداث الحالية تكتب بيانات الأعمال المسموح بها، ويجب مراجعة حمولة كل حدث جديد قبل إضافته.

إجمالي الصفحة واستعلام عناصرها عمليتان مستقلتان؛ لا snapshot مضمون مع كتابة أحداث جديدة بينهما. المقارنة الثنائية قد تحد من الاستفادة من فهرس النص؛ لا يوجد ادعاء أداء أرشيف كبير أو اختبار حمل في هذه الدفعة. الفهرس الحالي للشركة والتوقيت والمرجع باقٍ، ولا ترقية SQL جديدة (الإصدار 11).

## مواضع التنفيذ والتحقق

- `Application/Features/Audit/AuditService.cs`: التفويض والتحقق وحدود التاريخ وتفاصيل الحدث.
- `Application/Contracts/Audit/AuditReadFilter.cs`: حدود UTC الداخلية للقراءة.
- `Infrastructure/Persistence/SqlErpStore.Audit.cs`: التصفية والعد والصفحات في SQL مع المقارنة الثنائية؛ ليس جلب الأرشيف كاملًا للتصفية في التطبيق.
- `Api/Endpoints/AuditEndpoints.cs`: ربط query parameters والتفاصيل.
- `AuditTests.cs`: حدود اليوم والمنطقة الزمنية وأقصى تاريخ والهوية التاريخية والصفحات وعدم الأثر الكتابي والعزل والصلاحيات.
- `AuditSqlIntegration.cs`: السنة الكبيسة وحدود ticks وحالة الأحرف والمسافات والصفحات على SQL حقيقي.
- `HostedApiIntegration.cs`: استعلام مركب وتفاصيل الحدث ورفض التواريخ والصلاحيات عبر HTTPS/JWT.
