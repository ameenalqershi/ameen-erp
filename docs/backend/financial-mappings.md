# GL13 — ربط القوائم المالية والتدفقات

المصدر غير المعدل: `muhaseb-erp-analysis/docs/modules/GL.md`، GL13-F01–F17، BR02/BR09/BR18. المخرج خريطة عرض قابلة للتدقيق. هذه خدمة GL13 وليست ادعاء تنفيذ تقارير RPT03/RPT04 كاملة. الإضافة جديدة في هذه الدفعة.

## مطابقة الحقول

| المصدر | العقد والحماية |
|---|---|
| F01 الشركة | CompanyId من المسار والعضوية، جميع المراجع بمفتاح مركب للشركة |
| F02 الفرع | BranchId اختياري؛ null للشركة أو فرع فعال صريح عند الإنشاء، ثابت عند التعديل؛ يرشح الأستاذ عند المراجعة |
| F03 الحالة | IsActive ينشئها الخادم، وتغير بأمر status ذي سبب وإصدار متوقع |
| F04 اسم النموذج | Name نص مطلوب 1–200 |
| F05 نوع القائمة | StatementKind مطلوب: FinancialPosition, ProfitLoss, ChangesInEquity, CashFlow وفق RPT03/RPT04 وخارطة التقارير؛ بلا تعيينات حسابات افتراضية |
| F06 الإصدار | VersionCode رمز نصي مطلوب حتى 32، مستقل عن الإصدار الرقمي وUUID |
| F07 من تاريخ | EffectiveFrom تاريخ مطلوب؛ لا تراجع بتاريخ سابق له |
| F08 رمز البند | Lines.Code رمز مطلوب وفريد داخل النموذج |
| F09 البند الأب | ParentCode اختياري، يشير لبند ضمن النموذج دون دورة؛ FK داخلي لنفس الشركة والنموذج |
| F10 العنوان | Title نص مطلوب حتى 200 |
| F11 الحساب أو المجموعة | AccountId شرطي: حساب حركة أو مجموعة فعلية غير فارغة؛ يتوسع إلى حسابات الحركة التابعة، دون تداخل تصنيفات |
| F12 إشارة العرض | DisplaySign مطلوب Normal (+1) أو Reverse (-1)، لا تخمين للإشارة من نوع الحساب |

| F14–F17 التدقيق | CreatedBy من actor؛ CreatedAt وLastModifiedAt من ساعة الخادم؛ Revision عدد صحيح يبدأ 1 ويزيد مرة للتعديل/الحالة. Version UUID مستقل للتزامن |

## الأفعال والضوابط

المسار الأساسي `/api/v1/companies/{companyId}/financial-mappings`:

- GET بحث بمرشحات branchId/statementKind/isActive/search وصفحات؛ POST جديد؛ GET وPUT `/{id}` للحفظ والقراءة.
- POST `/{id}/status` تعطيل/تفعيل بسبب؛ تعطيل النموذج يمنع مراجعة جديدة ويحفظ القراءات واللقطات السابقة.
- POST `/{id}/review` يأخذ ExpectedVersion وAsOf، وينشئ لقطة ثابتة تحت معاملة الشركة؛ GET `/reviews/{reviewId}` للتفاصيل. المراجعة لا تزيد Revision لتعريف الخريطة.
- GET `/{id}/usage` يرجع استخدامات المراجعة الفعلية المحفوظة، لا عدد تقارير غير منفذة. GET `/{id}/audit-events` لسجل التعريف والحالة والمراجعة.

كل كتابة تتطلب Idempotency-Key. Configure لإنشاء/تعديل/حالة؛ Read للبحث والتفاصيل والمراجعة؛ Read+Audit لسجل التغييرات. جميع عمليات GL13 تتطلب AllBranches لأن دليل الحسابات ومراجعة غير المصنف على مستوى الشركة، حتى مع مرشح فرع. لا يمنح BranchId صلاحية قراءة الدليل الشامل لمستخدم محدود. لا يمكن للعميل إرسال هوية المنشئ أو الأوقات أو Revision أو الشركة أو حالة مباشرة داخل عقد الإنشاء.

صيغة آمنة ومحددة: `[CODE] + [CODE2] - ([CODE3])` مع إشارات أحادية؛ لا ضرب/قسمة أو ثوابت أو تنفيذ كود. الأقواس بعمق أقصى 32، السلسلة عبر البنود حتى 500، وعدد البنود 1–500، وحد تعقيد للمساهمات. ParentCode ترتيب عرض فقط؛ التجميع دائمًا صريح بصيغة لمنع الجمع الضمني المكرر. تحسب مراجع الصيغة بعد إشارة عرض البند المشار إليه ثم تطبق إشارة بند الناتج.

يرفض الحفظ دورات الأب أو الصيغ والمراجع المفقودة، التصنيف المباشر المكرر أو تداخل المجموعة مع حسابها، والاحتساب المتكرر داخل أي صيغة ولو بإشارتين متعاكستين أو عبر بند وسيط. لا يمنع ظهور حساب تفصيلي في بند المجموع الصريح؛ يمنع ظهوره مرتين في المجموع نفسه. يحفظ النموذج الناقص ليصححه المستخدم، لكن المراجعة ترجع `NeedsReview` و`account_unclassified` لكل حساب مطلوب غير مصنف، فلا تبدو الخريطة جاهزة. الحسابات المطلوبة جميع حسابات الحركة الفعالة، ومعها حسابات التاريخ المرحّل ولو عطلت لاحقًا؛ لا تفترض سياسات استثناء لفئة تقرير.

المراجعة تستخدم فقط Posted وReversed حتى AccountingDate المحدد، وتحتفظ بالأصل وعكسه المرحّل كأثرين تاريخيين؛ لا تدخل المسودات/المعتمدة غير المرحلة، ولا تعيد تسعير العملات. المبالغ من FunctionalDebit-FunctionalCredit بدقة decimal وبالعملة الوظيفية المسجلة. لا تمثل اللقطة نفسها تقرير تدفق نقدي قانونيًا أو قائمة أرباح عن فترة؛ نوع القائمة معلومة لتعريف الخريطة، وتقارير الفترة واستخراج التصنيفات القانونية عمل RPT03/RPT04 المستقل.

لقطة المراجعة تتضمن اسم وإصدار وتعريف البنود والصيغ والإشارات والحسابات الموسعة والمبالغ والأخطاء، وMappingVersion والتاريخ وهوية المراجع. لا تتغير بعد تعديل الخريطة أو دليل الحسابات؛ منع UPDATE/DELETE في EF ودور SQL التشغيلي. GL01 يعرض الخريطة ضمن استخدام الحساب ويحمي تعديل بنية الحساب أو تابع المجموعة المرتبطة حتى للنموذج المعطل؛ تغيير البنية يحتاج مسار تحويل منفصل.

## الترحيل والتحقق

`024_financial_mappings.sql` بعد 023، ذرية بقفل مخطط وسجل إصدار، قابلة لإعادة التطبيق، لا تنشئ نموذجًا أو تصنيفًا أو أثرًا ماليًا. مفاتيح شركة مركبة ومراجع أب داخل نفس النموذج؛ فهارس فريدة للاسم/النوع/الإصدار/النطاق ولأكواد وترتيب البنود. دور التشغيل يسمح باستبدال البنود وينفي تعديل/حذف المراجعات. لا يطبق API ترقية تلقائية عند التشغيل.

التحقق: FinancialMappingTests.cs للحقول والموجبات/السلبيات والأستاذ والعكس والمجموعة والصيغ والأمان والذرية؛ FinancialMappingSqlIntegration.cs للتزامن والقيود واستبدال البنود والصلاحيات والتراجع وإعادة المحاولة؛ SchemaUpgradeIntegration.cs لفشل DDL/تراجع/إعادة 023→024 مع بقاء التاريخ؛ HostedApiIntegration.cs لواجهات الإنتاج عبر HTTPS/JWT/SQL. دليل CI النهائي يسجل في PROGRESS.md وtwenty-numbering-mapping-tasks.md؛ لا تكتمل مهام القبول قبل نجاحه.
