# دليل وحدات القياس INV03

تنفذ هذه الدفعة بطاقة الوحدة العامة: الرمز والاسمان والوصف والرمز القياسي ودقة الكمية والملاحظات والحالة والإصدار، مع البحث والتعديل والتدقيق. أضيف لاحقًا ربط ITEM_UNIT والباركود والتحويلات وعرض استخدام الوحدة وقفل بنيتها في [INV04](items.md)، دون تنفيذ حركات المخزون.

## العقد

المسارات تحت `/api/v1/companies/{companyId}/units`، وكلها تتطلب هوية موثقة. القائمة مقسمة إلى صفحات وتقبل search/isActive/offset/limit، والبحث بالرمز أو الاسمين أو الرمز القياسي.

| المسار | الصلاحية والنتيجة |
|---|---|
| GET / | ledger.read؛ Page<UnitOfMeasure> |
| POST / | company.configure لكل الفروع؛ إنشاء وإيصال |
| GET /{id} | ledger.read؛ بطاقة الوحدة |
| PUT /{id} | company.configure لكل الفروع؛ تعديل بإصدار وسبب |
| POST /{id}/status | company.configure لكل الفروع؛ تفعيل أو تعطيل بإصدار وسبب |
| GET /{id}/audit-events | ledger.read + audit.read لكل الفروع؛ سجل البطاقة مع الصفحات |

الوحدات مشتركة للشركة، فلا يتطلب قارئ بطاقتها صلاحية جميع الفروع. لا تتيح عضوية شركة الوصول إلى وحدة شركة أخرى. الإنشاء والتعديل والحالة تتطلب Idempotency-Key وتحفظ البطاقة والتدقيق والإيصال في معاملة واحدة.

```json
{
  "code": "001",
  "name": "حبة",
  "standardCode": "EA",
  "quantityScale": 0,
  "description": "وحدة منفردة",
  "englishName": "Each",
  "notes": null
}
```

الرمز الداخلي فريد داخل الشركة، ويبقى نصًا لحفظ الأصفار البادئة. الرمز القياسي إدخال مستقل؛ يتحقق من شكله وطوله فقط دون الربط بسجل خارجي أو الادعاء باعتماد ضريبي. لا يشترط تفرده بين البطاقات. الأسماء حتى 200 حرف، والوصف الإلزامي حتى 500، والملاحظات حتى 2000، والرموز حتى 32. النص الفارغ مرفوض والاختياري يقبل null.

quantityScale إلزامي، ومجاله **0 إلى 6 حد تقني لهذه النسخة**؛ التحليل لا يحدد الحد الأعلى. صفر يعني عدم السماح بكسور عند استعمال الوحدة لاحقًا، ولا يعني تصفية أو تقريب كمية قائمة الآن. لا يوجد بعد مسار حركة كمية أو تحويل. إعداد الدقة هنا ليس تنفيذًا لحسابات مخزون.

التعديل يستقبل حقول البطاقة كلها، بما فيها optional بقيمة null عند حذفها، إضافة إلى expectedVersion وreason. Revision عدد صحيح يبدأ من 1، وVersion GUID للتزامن. إعادة الطلب المطابق لا تزيد الإصدار أو تكرر الأحداث. ربط الوحدة بصنف يقفل الرمز والرمز القياسي والدقة، ويمنع الصنف الفعال تعطيلها. تعرض مراجعها عبر GET /units/{id}/items؛ تفاصيل [INV04](items.md).

## التحويل والباركود

لا تحتوي الوحدة على معامل تحويل أو باركود. يرفض JSON الخصائص غير المعرفة، مثل conversionFactor. تحويل الكرتون إلى حبة يختلف حسب الصنف ويجب حفظه في ITEM_UNIT؛ وكذلك الباركود خاص بوحدة الصنف وفق INV04. لا يوجد معامل عام لجميع الأصناف ولا حساب تلقائي له في هذه الدفعة.

## الترقية والتحقق

طبّق السكربتات 001 إلى [008_units_of_measure.sql](../../backend/database/008_units_of_measure.sql) بالترتيب، ثم runtime-role.sql. التطبيق الحالي يتطلب أيضًا [ترقية مجموعات الأصناف 009](item-groups.md). الترقية ذرية وقابلة للإعادة، وتضيف جدولًا فارغًا دون افتراض دليل وحدات أو تغيير البطاقات والمبالغ السابقة. تفرد الرمز ونطاق الشركة ودقة الكمية والإصدار محمية بقيود SQL.

الاختبارات في [UnitTests.cs](../../backend/tests/Ameen.Erp.Tests/UnitTests.cs) و[UnitSqlIntegration.cs](../../backend/tests/Ameen.Erp.Tests/UnitSqlIntegration.cs)، مع اختبار فشل الترقية والتراجع وإعادتها، وطلبات HTTPS/JWT للإنشاء والتعديل والحالة والبحث والتدقيق ورفض معامل التحويل العام. لا توجد دعوى جاهزية دورة المخزون أو اختبار أداء إنتاجي.
