# GL01 — دليل الحسابات

المرجع: شاشة GL01 وحقولها الـ18 في [التحليل الأصلي](../../muhaseb-erp-analysis/data/screens.json)، ومخططي module-GL وdata-model. تضاف هذه الدفعة إلى دورة القيد الموجودة، دون واجهة أمامية. التحليل يمنع دورات الحسابات والترحيل للرئيسي وتغيير تصنيف الحساب المستخدم دون تحويل معتمد.

## العقود

الجذر `C = /api/v1/companies/{companyId}/accounts`، وكل المسارات تتطلب Bearer وعضوية شركة فعالة.

| الطريقة | المسار | العقد والصلاحية |
|---|---|---|
| GET | C | `Page<Account>`؛ `search/offset/limit`؛ ledger.read |
| POST | C | CreateAccountRequest؛ company.configure على كل الفروع |
| GET | C/{id} | Account؛ ledger.read |
| PUT | C/{id} | EditAccountRequest؛ company.configure على كل الفروع |
| POST | C/{id}/status | expectedVersion/isActive/reason؛ company.configure على كل الفروع |
| GET | C/{id}/usage | AccountUsage؛ ledger.read على كل الفروع |
| GET | C/{id}/audit-events | Page&lt;AuditEvent&gt;؛ ledger.read وaudit.read على كل الفروع |

الإنشاء يتطلب code/name/type/parentId/isPosting/isControl/requiresCostCenter/currencyCode/**normalBalance**. المراجع القابلة للإفراغ ترسل null. `englishName` و`notes` اختياريان. طبيعة الرصيد `Debit` أو `Credit` إلزامية صريحة، ويمكن أن تخالف الطبيعة المعتادة للتصنيف؛ مثل حساب مجمع استهلاك مصنف Asset وطبيعته Credit. الطبيعة وصف محاسبي، ولا تمنع الحركة المقابلة أو تقلب إشارات ميزان المراجعة.

```json
{
  "code": "001209",
  "name": "مجمع استهلاك المعدات",
  "type": "Asset",
  "parentId": null,
  "isPosting": true,
  "isControl": false,
  "requiresCostCenter": false,
  "currencyCode": null,
  "normalBalance": "Credit",
  "englishName": "Accumulated equipment depreciation",
  "notes": "حساب مقابل للأصل"
}
```

الرمز نص بطول أقصاه 32 ويحفظ الأصفار البادئة، والاسمان حتى 200، والملاحظات حتى 2000. null يفرغ الحقل الاختياري؛ النص الفارغ ومحارف التحكم مرفوضان. البحث يشمل الرمز والاسمين. حالة الأحرف في البحث تتبع collation قاعدة البيانات الحالية؛ لا يعد البحث تطابقًا حرفيًا حساسًا.

PUT يستبدل إعدادات البطاقة الواردة في نموذج الإنشاء، مع expectedVersion وreason إلزاميين وenglishName/notes الصريحين حتى عند null. حالة التفعيل لها أمر مستقل. كل كتابة تتطلب Idempotency-Key، وتُحفظ البطاقة والتدقيق وإيصال الطلب في معاملة واحدة. إعادة المفتاح نفسه والمحتوى نفسه تعيد الإيصال السابق بعد إعادة التحقق من الصلاحية؛ إصدار قديم بمفتاح جديد يعيد version_conflict.

## ضوابط التعديل والشجرة

- الأب موجود في الشركة، رئيسي وفعال ومن التصنيف نفسه؛ لا ربط بالنفس أو بأي حفيد، وتفحص سلسلة الأسلاف كاملة عند تعديل البنية.
- لا يصبح حساب له أبناء، حتى معطلين، حساب حركة. لا يغير تصنيفه بما يخالف تصنيف الأبناء. رمز الحساب فريد داخل الشركة، والعملة إن حددت معرفة فيها.
- الرمز والتصنيف والأب والرئيسي/الحركة والرقابي وإلزام المركز والعملة وطبيعة الرصيد حقول بنيوية. يقفل تعديلها إذا استخدم الحساب **أو أي من أحفاده** في قيد أو قالب دوري حالي. يشمل القيد المسودة والمقدم والمعتمد والمرحل والمعكوس والملغى، ويشمل القالب المعطل. لا تؤدي إعادة الأسماء والقيم نفسها إلى تعارض استخدام.
- الأسماء والملاحظات قابلة للتعديل للحساب المستخدم؛ لا تتغير المبالغ أو مراجع القيود أو شجرة تجميع التقارير. تظهر الأسماء الحالية في التقارير؛ لا توجد أسماء مؤرخة حسب تاريخ التقرير.
- تعديل البنية بعد الاستخدام يتطلب مسار تحويل معتمد غير منفذ بعد. لا توجد واجهة حذف للحساب، ولا تجاوز بقوة صلاحية مدير المنصة. التعطيل يمنع وجود أبناء فعالين؛ التفعيل يتطلب أبًا فعالًا. فحوص القيد تعيد التحقق من حالة الحساب عند التقديم والترحيل.

الضوابط البنيوية تنفذ داخل قفل الشركة نفسه المستخدم لإنشاء القيود والقوالب؛ لذلك لا يمكن لسباق التعديل وإنشاء قيد أن يترك قيدًا على حساب حُوّل إلى رقابي. القيود البنيوية إضافية في التطبيق، وليست SQL triggers قابلة لضمان سلامة كتابة مسؤول قاعدة البيانات خارج التطبيق.

## الاستخدام والتدقيق

`AccountUsage` يتضمن عدد الأبناء المباشرين، وعدد القيود المباشرة وسطورها، وعدد القوالب المباشرة، و`hasUsageInSubtree` للحساب وشجرته. `references` صفحة مرتبة حسب النوع ثم الرقم/الاسم ثم المعرف؛ السجل مرجع وثيقة أو قالب واحد مهما تكررت سطور الحساب. مرجع Journal يعرض الحالة، ومرجع RecurringTemplate يعرض Active/Inactive. المراجع تخص الحساب نفسه؛ استخدام الأبناء يدل عليه العلم المنفصل. لا تعرض مبالغ، لكنها تتطلب جميع الفروع حتى لا تكشف وثائق فرع محجوب.

التدقيق مخصص للحساب ويحتوي الإنشاء والتعديل والتفعيل والتعطيل. الأحداث الجديدة تحفظ snapshot كاملًا وإصداره؛ التعديل والحالة يحتفظان قبل/بعد وسبب وهوية ووقت من الخادم. الأحداث القديمة تظل بصيغتها الأصلية ولا تُعاد كتابتها. حقول أنشأه/وقت الإنشاء/آخر تعديل متاحة من التدقيق، وليست خصائص مباشرة جديدة على Account.

## الترقية وحدود التنفيذ

طبّق 001 ثم 002 ثم [003_account_cards.sql](../../backend/database/003_account_cards.sql)، ثم runtime-role.sql. 003 ذرية وقابلة للإعادة، ولا يطبقها API تلقائيًا؛ الإصدار 003 يضيف بطاقة الحساب، والتطبيق الحالي يتطلب أيضًا ترقيتي 004 و005 الموضحتين في [دليل التهيئة](currencies-and-cost-centers.md). تستكمل الحقول القديمة باسم إنجليزي وملاحظات null، وطبيعة ابتدائية Debit للأصول والمصروفات، وCredit للالتزامات وحقوق الملكية والإيرادات، مع Revision ابتدائي 1 للبطاقات القديمة، دون تغيير Version أو المعرفات أو الشجرة أو المبالغ. الرقم الابتدائي للبطاقات القديمة بداية عدّ التعديلات بعد الترقية، ولا يدعي استعادة عدد تعديلات غير مسجل سابقًا.

الطبيعة المستنتجة للبطاقات القديمة ليست إثباتًا محاسبيًا لطبيعة الحسابات المقابلة؛ تحتاج مراجعة قبل ترقية بيانات فعلية. الحساب القديم المستخدم لا يحصل على استثناء من قفل التعديل؛ تصحيحه يتبع تحويلًا معتمدًا عند تنفيذ ذلك المسار. لا تؤثر القيمة الابتدائية في حساب أرصدة التقارير الحالية.

سجل الاستخدام يغطي الأستاذ والقوالب الحاليين؛ يجب توسيعه عند إضافة الذمم والمخزون والأصول وبقية المراجع. حذف مرجع من قالب غير مولد أو استبدال سطور مسودة قد يزيل الاستخدام الحالي إن لم يبق مرجع آخر؛ سجل التدقيق يبقى ولا يعد مرجع حركة حيًا. قراءة الاستخدام تجمع البيانات داخل التطبيق ولا توفر snapshot متعدد الاستعلامات أو اختبار حمل كبير. GL01-F17 هو `Revision` عدد صحيح من الخادم يبدأ من 1 ويزداد مع حفظ التعديل والحالة، ولا ترفعه الإعادة أو العملية المرفوضة. `Version` رمز UUID تقني مستقل للتزامن. هذه الدفعة لا تعلن اكتمال الشاشة أو النظام.
