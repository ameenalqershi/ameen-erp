# CORE SPEC07 — تدقيق الدورات وسيناريوهات القبول (5 نوفمبر 2026)

## النطاق وحدود الإثبات

- تمت قراءة المصدر الأصلي كاملًا: `muhaseb-erp-analysis/docs/07-workflows-and-acceptance.md`.
- المصدر يصرح بأن سيناريوهات AT اختبارات قبول لتنفيذ النظام مستقبلًا، وليست اختبارات منفذة على تطبيق محاسبي قائم.
- رُبطت السيناريوهات الثلاثون AT01–AT30 بصفحات Notion المقابلة، مع الاحتفاظ بمعايير النتيجة المتوقعة كما وردت في المصدر.
- لا يعني ربط AT بالمهمة أن الخدمة أو API أو SQL أو JWT أو التزامن أو الأثر المحاسبي قد اجتاز الاختبار.

## ملخص التغطية

| النطاق | سيناريوهات القبول | الملاحظة |
|---|---|---|
| الترحيل والفترات ومنع التكرار | AT01–AT03 | تتطلب اختبارًا سلبيًا وذرية/idempotency على SQL |
| البيع والمخزون والتسليم والمرتجعات | AT04–AT07 | تتطلب تزامن تخصيص الكمية وربط سطور المصدر والهدف |
| التحصيل والعملات والتقييم | AT08–AT10 | لا تحسم هذه المصفوفة سياسة تقييم أو عكسًا محاسبيًا غير معتمد |
| التحويل والجرد والتكلفة والافتتاح | AT11–AT14 | تتطلب مطابقة حركة/قيمة ومنع إعادة الاستيراد |
| التقارير والأصول ونقطة البيع | AT15–AT17 | تتطلب بيانات زمنية ودفاتر مساعدة واختبار أثر الوردية |
| الفوترة الإلكترونية والصلاحيات والإقفال | AT18–AT21 | يتوقف جزء منها على قرار الدولة والصلاحيات ومصادر مكتملة |
| الرواتب والتصنيع والمشروعات | AT22–AT24 | وحدات/سياسات قطاعية مستقلة؛ لا تستنتج سياسة جديدة |
| عزل الشركات والشيكات والعكس والاستعادة والتدفقات | AT25–AT30 | اختبارات تكامل عبر الوحدات؛ لا تساوي قبولًا تشغيليًا بمجرد وجود الهيكل |

## سجل التتبع AT01–AT30

المصفوفة المرفقة `core-spec07-acceptance-traceability.csv` تحتوي 30 صفًا، وتربط كل سيناريو بمرجع Notion وشاشاته ومدخلاته ونتيجته المتوقعة والعائق/التبعية. تم الحفاظ على IDs الأصلية ولم تُنشأ سيناريوهات بديلة.

## ملاحظات الاعتماد والتعارض

1. AT09 وAT10 يذكران أسعار صرف وأرباح/خسائر عملة وأثر تقييم. لا يُستخدم المثال الرقمي لإقرار سياسة تقييم أو عكس غير محسومة؛ يجب أن يتوافق التنفيذ مع قرار معتمد.
2. AT13 يفترض توزيع تكلفة إضافية بالتساوي في المثال؛ لا يعمم هذا على طرق توزيع الشحن أو تقييم المخزون دون اعتماد السياسة.
3. AT18 يتطلب إعادة المحاولة بنفس الهوية بعد انقطاع الاتصال؛ يجب أن يبقى أثر التكرار fail-closed حتى قبول عقد TAX/OUTBOX.
4. AT19 يطلب منع كشف التكلفة في الشاشة والملف والطباعة والاستجابة؛ إخفاء عنصر الواجهة وحده ليس دليل قبول.
5. AT22–AT24 تعتمد على وحدات HR/MFG/PRJ وسياساتها؛ نجاح أساس مشترك لا يثبت تشغيلها.
6. AT29 يحتاج اختبار استعادة نسخة تجريبية ومطابقة الوثائق والدفاتر والمرفقات؛ لا يُستبدل بجرد migrations أو اختبار schema.
7. AT30 يميز بين التحويل الداخلي وصافي التدفق؛ يلزم عقد تقرير RPT04 معتمد ومطابقة الحركة.

## بوابة الإغلاق

- 30/30 سيناريو مصدرية مرتبطة بمهام Notion.
- لا يوجد ادعاء بأن أي سيناريو نُفذ أو نجح في التطبيق؛ دليل التنفيذ `not-verified`.
- أي سياسة أو عقد غير محسوم يبقى عائقًا مسمى ولا يحول إلى default.
- قبول SPEC07 يتطلب مراجعة SUPERVISOR والتحقق من روابط المهام؛ أما اجتياز السيناريوهات فيتطلب تشغيلها على التطبيق مع أدلة SQL/HTTP/JWT/التزامن/الأثر حسب الحالة.
