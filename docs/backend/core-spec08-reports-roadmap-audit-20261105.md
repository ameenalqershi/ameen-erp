# CORE SPEC08 — تدقيق عقد التقارير وخارطة التنفيذ (5 نوفمبر 2026)

## النطاق وحدود الإثبات

- تمت قراءة المصدر الأصلي كاملًا: `muhaseb-erp-analysis/docs/08-reports-and-roadmap.md`.
- استُخرجت 19 مواصفة تقرير و7 مراحل تنفيذ، وربطت مواصفات التقارير بمهام RPT-CONTRACT-01..19 الموجودة في Notion.
- هذا التدقيق لا ينفذ استعلامات تقارير ولا يثبت اتزان دفتر أو صحة رصيد أو أداء تصدير؛ حالة القبول لكل عقد تقرير `not-verified`.
- لم يُحدد المصدر تقنية أو موعدًا أو تكلفة تنفيذ؛ لا نضيف أيًا منها.

## ضوابط مشتركة لعقد التقرير

1. سياق كل تقرير: الشركة والفروع والفترة والعملة ونمط التحويل والحالة ووقت الاستخراج.
2. Drill-through إلى المصدر لا يتجاوز صلاحية المستخدم أو نطاق الشركة/الفرع.
3. مرشحات التصدير تطابق المرشحات الظاهرة؛ لا تتسرب أعمدة/صفوف محجوبة.
4. الإجمالي التجميعي يحسب من السطور الأصلية مرة واحدة، لا من إجماليات متداخلة.
5. يجب توثيق طريقة التعامل مع التاريخ والعملة والشرائح قبل اعتبار التقرير مطابقًا.

## نتائج التدقيق والحدود

1. 19/19 عقد تقرير مرتبطة بمهام RPT-CONTRACT القائمة؛ لم تُنشأ عقود بديلة.
2. 7/7 مراحل مرتبطة بمراجع قرار أو سيناريو قبول موجودة؛ لا يعني ذلك اعتماد تسلسل زمني ملزم.
3. جميع نتائج القبول في هذا التدقيق `not-verified`; لا استعلام أو تقرير أو مطابقة رصيد جرى تشغيله ضمن هذه المهمة.
4. الأرقام/المعادلات في التقرير شروط قبول من المصدر وليست نتائج اختبار فعلية.
5. لا يُنشأ محرك تقرير مستقل لكل مدخل؛ يجب أن تعيد مداخل القسم ومركز التقارير استخدام عقد التقرير نفسه دون تجاوز الصلاحيات.
