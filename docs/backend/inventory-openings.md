# INV06 — تجهيز المخزون أول المدة

المرجع: `muhaseb-erp-analysis/docs/modules/INV.md` (INV06)، وعلاقة DOCUMENT/DOCUMENT_LINE/ITEM/LOT في data-model، ومسار document-lifecycle. التنفيذ الحالي دورة تجهيز حتى الاعتماد ومعاينة القيمة. لا يوجد STOCK_MOVEMENT أو قيد أستاذ أو رصيد افتتاح ناتج عن حفظ/اعتماد المستند؛ لا يوجد endpoint للترحيل.

## عقد API

تحت `/api/v1/companies/{companyId}/inventory-openings`:

| العملية | المسار | الصلاحية |
|---|---|---|
| إنشاء | POST / | inventory.opening.write ضمن الفرع |
| تعديل سطور وبيان | PUT /{id} | inventory.opening.write ضمن الفرع |
| بحث | GET / | ledger.read ضمن الفروع المسموحة |
| تفاصيل | GET /{id} | ledger.read ضمن فرع المستند |
| تقديم | POST /{id}/submit | inventory.opening.write |
| إعادة مسببّة | POST /{id}/return | inventory.opening.approve |
| اعتماد | POST /{id}/approve | inventory.opening.approve، بواسطة شخص آخر |
| إلغاء مسودة | POST /{id}/cancel | inventory.opening.write |
| معاينة قيمة | GET /{id}/valuation-preview | ledger.read ضمن الفرع |
| سجل تغييرات | GET /{id}/audit-events | audit.read شامل الشركة وقراءة المستند |

الكتابة تتطلب Idempotency-Key، والتعديل والانتقالات ExpectedVersion. أسباب التعديل والإعادة والإلغاء مطلوبة. الصلاحيات الجديدة لا تمنح تلقائيًا لأعضاء قدامى، ولا يستلزم journal.write امتلاك صلاحية مخزون. مسؤول الشركة يمنحها لعضو آخر وفق قواعد SYS07 الحالية.

البحث يدعم branchId/state/search/offset/limit. عبارة البحث تطابق الرقم أو مرجع الجرد أو البيان. الحساب العددي والصفحات محصوران في الفروع المسموحة.

## المستند والسطور

يسجل المستند الفرع والمخزن والسنة والفترة المستنتجين من تاريخ الأثر، وتواريخ الوثيقة والأثر والقطع، ومرجع الجرد والمرجع الخارجي والبيان. الترقيم الحالي `IO-{FiscalYear.Code}-{sequence:000000}` داخل الشركة والسنة، ذرّي ومنفصل عن أرقام GL. هذه صيغة أولية إلى حين SYS09؛ ليست سياسة ترقيم قابلة للتهيئة.

العملة الوظيفية فقط وسعر 1 في هذه الدفعة؛ ترفض الأجنبية أو سعرًا آخر صراحة. وجود أي مستند افتتاح، حتى ملغى، يقفل تغيير عملة الشركة الوظيفية لحماية البيانات التاريخية. تعديل المستند يغير البيان والسطور فقط؛ لتصحيح فرع/مخزن/تاريخ/مرجع جرد يُلغى المستند وهو مسودة ويُنشأ آخر.

يقبل المستند 1–200 سطر. يتحقق من الصنف الفعال غير الخدمي ووحدة معرفة عليه ووحدته الأساسية الفعالة، ويستخدم التحويل الدقيق نفسه في INV04. تحفظ Quantity وFactorToBase وBaseQuantity ووحدة الإدخال ورمز الصنف وإصداره. كمية السطر موجبة وتخضع لدقة الوحدة؛ لا تقريب للتحويل.

UnitCost تكلفة **وحدة الإدخال** غير سالبة حتى 6 خانات. Value = Quantity × UnitCost مقربة لكل سطر إلى دقة العملة الوظيفية، بنمط AwayFromZero؛ مجموع السطور هو معاينة القيمة. تمنع القيم المتجاوزة لـdecimal(20,6). هذه سياسة حساب أولية موثقة يلزم اتساقها مع محرك التقييم عند تنفيذه.

الصنف المتتبع يتطلب IdentityId فعالًا للصنف والشركة ونوع التتبع نفسه. تحفظ LotNumber/SerialNumber وإصدار الهوية كما كانت عند الحفظ. التسلسل يساوي وحدة أساسية واحدة ولا يتكرر داخل المستند. لا توجد حجوزات تمنع إدخاله في مسودتين؛ منع تكرار الأثر بين المستندات مطلوب عند الترحيل.

## الحالات والحماية

Draft → Submitted → Approved. يستطيع المراجع إعادة Submitted إلى Returned مع سبب؛ حفظ التصحيح يعيد Returned إلى Draft. يلزم تقديم جديد بعد التصحيح. الإلغاء من Draft فقط حسب المخطط. المنشئ لا يعتمد مستنده حتى إن امتلك صلاحية الاعتماد. Approved وCancelled محميان من التعديل في API وحراسة EF، والسطور لا تعدل خارج حفظ مسودة/تصحيح مع إصدار مالك متغير.

تُعاد مراجعة الفترة والفرع والمخزن والأصناف والوحدات والهويات عند التقديم والاعتماد. إذا تغير إصدار الصنف أو الهوية، يرفض الإجراء ويطلب إعادة حفظ التصحيح، ولا يستبدل التاريخ بصمت. التراجع عند فشل التدقيق يعيد المستند والسطور والإيصال والتسلسل؛ إعادة الطلب تعيد نفس النتيجة مع إعادة فحص صلاحية العضو.

كل مستند غير Cancelled يمنع إقفال فترته. تضيف معاينة GL11 الفحص no_pending_inventory_openings والعدد PendingInventoryOpeningCount؛ تفاصيل المستندات عبر بحث INV06. ما زال GeneralLedgerOnly=true لأن الإقفال الشامل للدفاتر غير منفذ. المعاينة لا تحجز الفترة ولا تحفظ أثرًا.

## حدود الاستكمال

- لا ترحيل أو مخزون أو قيد رقابة أو عكس أو طباعة. CanPost=false دائمًا، مع PostingBlocker=inventory_ledger_and_opening_reconciliation_pending. القيمة المعروضة لا تثبت مطابقة حساب الرقابة.
- يلزم دفتر STOCK_MOVEMENT وسياسة تكلفة ومصدر افتتاح آلي للأستاذ وربط GL02 يمنع الافتتاح المزدوج، ثم ترحيل ذري واختبارات السباق والإقفال والعكس.
- الحالة Approved نهائية في نطاق التجهيز الحالي؛ لا تعد الدورة جاهزة لتشغيل افتتاح إنتاجي قبل إضافة الترحيل. الفترات التي تضمها تبقى ممنوعة من الإقفال.
- شروط تاريخ القطع وعلاقته ببداية التشغيل ومرجع الجرد مع SYS13، والعملات الأجنبية، وقيم الجودة والإتاحة والصلاحية، وتوزيع مواقع المخزن، غير مكتملة. تواريخ القطع والجرد تسجل ولا تفترض سياسات غير موجودة.
- F21 جزئي: الرقم التسلسلي يختار بمرجع هوية ويعاد كنص محفوظ، وليس إدخال نص حر كما في التحليل. F08/F09 جزئيان للعملة الوظيفية، وF12 جزئي لدورة ما قبل الترحيل.
- بيانات المدخلات المأخوذة تاريخيًا تحفظ في السطر؛ لا يُعلن أن البطاقة المرجعية مقفلة لكل تعديل بمجرد مسودة. عند الترحيل يجب إضافة حراسة الاستخدام للبطاقات والحسابات والهويات.

## قاعدة البيانات والتحقق

ترقية 014 بعد 013 تضيف InventoryOpenings/InventoryOpeningLines، ومراجع مركبة حسب الشركة، وقيود الحالات والاعتماد والقيم وفهارس الترقيم والبحث. طبّق runtime-role.sql بعدها لمنح حذف سطور المسودة فقط. لا يغير السكربت أي رصيد قديم، ويُختبر بفشل DDL ثم إعادة التطبيق.

InventoryOpeningTests: 13 حالة وظيفية تشمل دورة المراجعة والإصدارات والعزل والتحويل والتسلسل والتراجع وإقفال الفترة. InventoryOpeningSqlIntegration: إعادة متزامنة، تسلسل بلا ازدواج، فشل تدقيق واستعادة، تحرير بحساب runtime، حماية المعتمد، بحث وموانع إقفال. HostedApiIntegration: دورة المستند عبر HTTPS/JWT/SQL. نتائج التشغيل الفعلية في verification-results.json.
