## Node ownership and flow boundaries

- **DGM-16 / system-map:** `U` users; `S` SYS; `L` TAX; `P` PUR + IMP; `I` INV + MFG; `A` SAL + POS; `T` CASH; `G` GL; `X` FA + HR + PRJ; `R` RPT/GL close; `C` COST. Edges `P/I/A/T/X → G` and `G → R/C` designate requested accounting consequences, **not proof of source implementations**. Exact financial posting must be established by each owning module and GL tests before closing any edge.
- **DGM-17 / document-lifecycle:** `D` draft, `V` submitted, `C` returned, `A` approved, `E` cancelled, `P` posting validation, `F` no-effect failure, `J` posted immutable, `N` linked correction. The `D→V→C→D` correction loop is intentional; no generic acyclicity guard is introduced. Executable acceptance currently applies only to specific implemented sources; no invented universal endpoint.
- **DGM-18 / purchase-to-pay:** `R/Q/G/D/M/H/P/S/A` cross PUR/INV/GL/CASH. `G/D→M` requires receipt versus direct purchase to avoid double-acceptance; `M→H/P` requires an **approved** tolerance policy (none is inferred); `P→S→A` requires real AP/GL/settlement.
- **DGM-19 / sale-to-cash:** `C/O/H/R/D/I/F/E/P/A` cross SAL/INV/TAX/CASH/GL. `D/I→F` requires one inventory effect; `F→E` country issuance checks; `F→P→A` AR/payment allocations. Quote/credit checks and exceptions must be approved, not invented in CORE.

## Reproducible verification and limits

`backend/scripts/check_core_flowchart_graphs.py` validates that all four original indexes, Mermaid source files, SVG XML and traceability rows agree. It rejects malformed nodes/edges, duplicates, foreign references, unconnected stages and unsupported trace statuses, while retaining legitimate loops and multiple entry paths. `backend/scripts/tests/test_core_flowchart_graphs.py` adds **nine** positive/negative regression cases and runs under current `verify.py` unittest discovery. No changes to original SVG, Mermaid, API, SQL, authorization or financial behavior.

The checker tests source graph integrity and **does not** independently prove that every arrow has a backing API transaction. DGM-16–19 remain **partial** until missing operational paths and each module's documented acceptance are closed; DGM-18/19 existing feature traceability remains `not-started`. Passing source checks cannot close incomplete sources.
