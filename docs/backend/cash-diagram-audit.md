# DIAG-module-CASH — تدقيق خريطة الصناديق والبنوك

**النطاق:** تدقيق تغطية وثيقة خريطة التنقل؛ ليس تنفيذًا لوظائف مالية أو إغلاقًا لشاشات CASH. يربط هذا الدليل المخطط الأصلي بالحقول وقواعد الأعمال وواقع اختبارات الخلفية، دون تعديل أي ملف أصلي.

## المراجع الثابتة

- Mermaid الأصلي: muhaseb-erp-analysis/diagrams/source/module-CASH.mmd
- العرض الأصلي: muhaseb-erp-analysis/diagrams/svg/module-CASH.svg
- شرح الشاشات والضوابط: muhaseb-erp-analysis/docs/modules/CASH.md
- قاموس الحقول: muhaseb-erp-analysis/data/fields.csv
- التنفيذ الفعلي: docs/backend/screens-implementation.csv وdocs/backend/fields-implementation.csv وdocs/backend/PROGRESS.md
- التحقق القابل للإعادة: python3 backend/scripts/audit_cash_diagram.py

## نتيجة مطابقة العقد والعلاقات

المخطط يحوي **15 عقدة** (جذر + 3 قوائم + 11 شاشة) و**14 علاقة تنقل موجهة** بلا تكرار أو عقد يتيمة. القوائم ومساراتها مطابقة للشرح؛ رموز الشاشات الأحد عشر موجودة مرة واحدة في SVG، وجميعها ممثلة في سجل التنفيذ وفي دليل CASH.md.

| القائمة | علاقات التنقل المطابقة حرفيًا للمخطط الأصلي |
| --- | --- |
| الجذر | root → cat0، root → cat1، root → cat2 |
| البيانات الأساسية | cat0 → CASH01 → CASH02 |
| العمليات | cat1 → CASH03 → CASH04 → CASH05 → CASH06 → CASH07 → CASH08 |
| الإجراءات | cat2 → CASH09 → CASH10 → CASH11 |

**ملاحظة تفسيرية ملزمة:** أسهم المخطط هي ترتيب *تنقل* حسب نص المصدر، وليست دليلًا على ترتيب ترحيل أو اعتماد مالي. الاعتماديات التشغيلية تُستمد من شرح كل شاشة، وليس من اتجاه السهم.

## ضوابط القبول والتزامن والتدقيق

- **CASH01**: فحوص الاستخدام والربط والفرع والعملة والأمين والتزامن والتدقيق والإصدارات متاحة في CashBoxTests.cs وCashBoxSqlIntegration.cs وSqlIntegration.cs ومسارات API. لا يعني ذلك وجود أرصدة متاحة أو سماح سحب.
- **CASH02**: BankAccountFoundationTests.cs وBankAccountSqlIntegration.cs تتحققان من العقد البنيوي والقيود والذرية وقبول IBAN. لم يُمنح صلاحية تشغيل أو رفع حظر EF، ولا يوجد API مصرفي معلن.
- **CASH03**: CashReceiptFoundationTests.cs وCashReceiptSqlIntegration.cs يثبتان حفظ الحقول بالـSQL المؤقت والعزل والدقة ورفض كتابات EF قبل السياسات؛ وCashReceiptAllocationTests.cs يفحص حد التخصيص domain فقط. لا توجد قاعدة فاتورة SAL11 حية أو خصومات مرحّلة أو ترحيل GL06 أو API/شيك تشغيلـي؛ كل قبول مالي تشغيلي محجوب.
- **CASH04–CASH06 وCASH10**: لم تبدأ عملياتها؛ لا يُدعى اختبار SQL/HTTPS أو تدقيق فعلي لها.
- **CASH09**: ChequeMovementFoundationTests.cs وChequeMovementSqlIntegration.cs تغطيان ربط حركة لشيك واحد وعزل الشركة وفحوص المراجع والسعر/العمولة والـSQL المؤقت وقفل EF. لا توجد قائمة حالات مصادق عليها أو تنفيذ تحويل حالة أو دفتر تحصيل/إلغاء؛ لا تغلق الشاشة التشغيلية.
- **CASH07/CASH08**: ChequeFoundationTests.cs وChequeSqlIntegration.cs يتحققان من البنية SQL 035/036 والعزل والدقة وسلامة الحظر EF؛ لا يوجد قبض أو صرف شيكات حقيقي أو دورة حالات CASH09 أو تسوية ذمة أو خصم بنك؛ الشاشتان جزئيتان فقط.
- **CASH11**: CashCountFoundationTests.cs وCashCountSqlIntegration.cs يختبران الهيكل البنيوي فقط مع SQL مؤقت ورفض كتابة EF. لا تدّعي هذه الاختبارات تحصيلًا أو محضرًا مرحلًا أو رصيد دفتر أو صلاحية اعتماد؛ أي استخدام تشغيلي ممنوع حتى اكتمال سياسة التسوية وGL03.

## نتيجة التدقيق وقاعدة الصيانة

**DIAG-module-CASH مغلق كتدقيق مستقل وفق CI #41661194098 السابق؛ يستمر التحقق عند كل تغيير**: جميع عقد التنقل والحواف والحقول والارتباطات مع سجلات الحالة موجودة ولا يوجد تعارض بين رموز Mermaid وSVG ودليل المصدر. يستمر سجل التنفيذ ليذكر الشاشات الجزئية والمتوقفة، دون اختراع سياسات أو تعديل المخطط الأصلي.

أي تعديل لاحق لشاشة أو رابط أو عدد حقول معتمد يستلزم إعادة تشغيل audit_cash_diagram.py ومراجعة هذه المصفوفة وNotion قبل تحديث حالة أي شاشة. ليس نجاح تدقيق الخريطة شهادة بإكمال قسم CASH.
