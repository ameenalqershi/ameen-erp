# GL03-FG08 — حقول تدقيق اليومية

| حقل المصدر | التنفيذ |
|---|---|
| GL03-F25 — أنشأه | CreatedBy من هوية المنشئ؛ لا يسمح عقد الأوامر بإرساله أو استبداله |
| GL03-F26 — وقت الإنشاء | CreatedAt خادمي ثابت |
| GL03-F27 — رقم إصدار التعديل، عدد صحيح | Revision يبدأ من 1؛ Version UUID مستقل لقفل التزامن |
| GL03-F28 — آخر تعديل، تاريخ ووقت | LastModifiedAt خادمي محفوظ في SQL وفي تفاصيل اليومية وقوائمها والمعالجة |

يزداد Revision مرة لكل أمر تعديل أو انتقال حالة ناجح، ومرة على الأصل عند حجز عكس أو تحريره أو اكتمال ترحيله. يبدأ القيد العكسي أو المولد نفسه بإصدار 1؛ إنشاء قيد المخزون وترحيله في معاملة المصدر الواحدة يبقى عملية إنشاء واحدة. تظل OpeningRevision وOpeningModifiedAt الخاصة بـGL02 محفوظتين ومتوافقتين مع سلوكهما السابق.

الإعادة بالمفتاح نفسه، والطلب بإصدار قديم، وفشل التدقيق أو الحفظ لا تزيد الإصدار. تحفظ المعاملة القيد والتدقيق والإيصال والترقيم والأثر وروابط العكس معًا. لا يسمح الحفظ بإعادة كتابة المحتوى المالي لقيد مرحل؛ إضافة الإصدار لا تخفف هذا الضابط.

## ترقية 022

تتطلب 021، وتقفل ترقية المخطط داخل معاملة واحدة. تعيد بناء الإصدار من أحداث التعديل وانتقالات الحالات، ومن أحداث مسودات العكس وإلغائها المرتبطة بالأصل. لا تعد أحداث GL02 الإضافية لنفس رابط العكس مرتين، ولا تعد إنشاء قيد المخزون المرحل انتقالًا مستقلًا عن إنشائه. يحتفظ السجل بلا أحداث تغيير برقم أساس 1؛ لا تُختلق تغييرات سابقة غير مدققة. آخر تعديل مأخوذ من أحدث وقت موثق بين الإنشاء والترحيل وأحداث التغيير.

تحفظ الترقية أرقام المستندات ومبالغها وتواريخها وUUID ومصادرها. تستخدم SQL ديناميكيًا ثابتًا لتأخير تجميع العبارات التي تشير إلى أعمدة جديدة حتى وجودها. يفحص الاختبار فشل DDL والتراجع الكامل، ثم التطبيق مرتين واستعادة إصدار ووقت القيد الأصلي والعكس من التاريخ.

## دليل القبول

اختبارات JournalAuditTests لدورة التعديل والمراجعة والاعتماد والترحيل وحجز العكس وإلغائه وإعادة الطلب والتراجع؛ SQL للتزامن وفشل التدقيق وترقية التاريخ، وHTTPS/JWT لقراءة الرقم الصحيح والوقت الخادمي ورفض تزويره، وOpenAPI لنوعي integer وdate-time. نتائج التشغيل الفعلية تحفظ في PROGRESS وverification-results؛ لا يعني قبول هذه الحقول اكتمال GL03 أو GL.
