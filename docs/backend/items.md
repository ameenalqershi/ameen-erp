# بطاقة الصنف ووحداته INV04

تضيف هذه الدفعة ITEM وITEM_UNIT وفق ربط المخطط: بطاقة الصنف، وحداته الخاصة، معامل كل وحدة إلى الأساسية، الباركود وسعر البيع، والبحث والتعديل والحالة والتدقيق وتحويل كمية دقيق. لا تنفذ دفتر مخزون أو كميات متاحة أو تسعير بيع تعاقدي أو ضرائب أو دفعات وأرقام تسلسلية فعلية.

## نطاق القوائم والسياسات

التحليل لا يسرد القيم الكاملة لقائمتي النوع والتتبع. اعتمد التنفيذ نطاقًا أوليًا من غرض INV04 وهوية المخزون في INV05: Goods=سلعة، Service=خدمة، Material=مادة، Product=منتج؛ وNone=دون تتبع، Lot=دفعات، Serial=تسلسل. هذه ترجمة تنفيذية أولية وليست قائمة سياسة مؤكدة أو إثبات مطابقة لمنتج المتكامل. لا يقبل API قيماً أو أرقام enum أخرى. حقلا النوع والتتبع معلنان جزئيين في مصفوفة المطابقة.

الخدمة لا تقبل تتبع مخزون أو مدة صلاحية أو حد إعادة طلب. غير الخدمة يتطلب حسابي المخزون والتكلفة في المجموعة، إضافة لحساب المبيعات الإلزامي. المجموعة والحسابات والوحدات وسلسلة آباء المجموعة يجب أن تكون فعالة وفي الشركة. لا يوجد تجاوز لإعداد حسابات المجموعة داخل الصنف ولا ربط ضريبة بعد.

مدة الصلاحية أيام موجبة إن أرسلت، وتتطلب تتبعًا؛ لا تنشئ تاريخ صلاحية لدفعة. التتبع التسلسلي يتطلب وحدة أساسية بدقة صفر. حد إعادة الطلب غير سالب ودقيق بحسب الوحدة الأساسية؛ لا يولد طلب شراء آليًا.

## العقد والمسارات

تحت `/api/v1/companies/{companyId}/items`:

| المسار | السلوك |
|---|---|
| GET / | صفحات مع search/groupId/isActive/offset/limit؛ بحث بالرمز أو الاسمين أو باركود مطابق |
| POST / | إنشاء بطاقة ووحداتها معًا |
| GET /{id} | البطاقة ووحداتها |
| PUT /{id} | استبدال البطاقة ووحداتها، expectedVersion وreason مطلوبان |
| POST /{id}/status | expectedVersion/isActive/reason |
| GET /{id}/audit-events | أحداث البطاقة بصفحات |
| GET /{id}/convert-quantity?unitId=...&quantity=2 | معاينة تحويل إلى الوحدة الأساسية دون حركة مخزون |

القراءة بصلاحية ledger.read. الكتابة بصلاحية company.configure لكل الفروع ومفتاح Idempotency-Key؛ التدقيق يحتاج أيضًا audit.read لكل الفروع. الوحدات والمجموعات والأصناف مشتركة للشركة؛ لا تورث صلاحيات إضافية من شجرتها.

إنشاء الخدمة المثال التالي يتطلب معرفات فعلية للمجموعة والوحدة:

```json
{
  "code": "001",
  "name": "خدمة تجريبية",
  "type": "Service",
  "tracking": "None",
  "groupId": "11111111-1111-1111-1111-111111111111",
  "baseUnitId": "22222222-2222-2222-2222-222222222222",
  "units": [
    {"unitId":"22222222-2222-2222-2222-222222222222","factorToBase":"1","barcode":"000123","salePrice":"10.00"}
  ]
}
```

الحقول الاختيارية الأخرى shelfLifeDays وreorderLevel وenglishName وnotes. نموذج التعديل يطلب جميع حقوله صراحة مع null للاختياري. Revision عدد صحيح يزيد لكل تعديل أو حالة، وVersion GUID للتزامن. لا يقبل تعديل وحدة منفردة خارج معاملة البطاقة؛ تستبدل السطور بعد التحقق، والتدقيق والإيصال وحذف القديم وإضافة الجديد ضمن معاملة واحدة.

## الوحدات والدقة والباركود

يجب إرسال الوحدة الأساسية ضمن units بمعامل واحد، دون تكرار unitId، ومن 1 إلى 100 وحدة. المعامل موجب وبحد أقصى 6 خانات عشرية، ويجب أن يمثل كمية دقيقة في الوحدة الأساسية. الحد العددي أقل من 10^14، وهو حد تقني للكمية والمعامل والسعر. الكميات والأسعار نصوص عشرية دقيقة في JSON، واستعلام التحويل يرفض الكسور التي يستلزم تمثيلها تقريبًا والصيغة الأسية.

مثال: كرتون لصنف أول بمعامل 12، ولصنف آخر بمعامل 24؛ كلاهما يستخدم بطاقة الكرتون العامة نفسها. المعامل يخص ITEM_UNIT. إذا كانت الأساسية لا تقبل كسورًا فإن نصف كرتون بمعامل 12 يساوي 6، لكن 0.01 كرتون يرفض لأنه يعطي 0.12 حبة. لا يوجد تقريب صامت أو تحويل عام في دليل الوحدات. التحويل استعلام يحمل ItemVersion؛ يجب على المستندات المستقبلية إعادة التحقق عند التنفيذ ولا تعتمد المعاينة كحجز.

الباركود نص حتى 128 حرفًا يحفظ الأصفار البادئة وحالة الأحرف، فريد داخل الشركة عبر جميع وحدات الأصناف حتى المعطلة. الفراغ الطرفي يزال، والنص الفارغ ومحارف التحكم مرفوضة. لا تحقق من رقم فحص GS1 أو نوع ماسح ضمن هذه الدفعة. null يعني عدم وجود باركود. سعر البيع اختياري وغير سالب **بالعملة الوظيفية للشركة في هذه النسخة**، ودقته دقة تلك العملة. لا يمثل قائمة أسعار بعملات متعددة ولا سعرًا شاملًا للضريبة. تحفظ أحداث تدقيق الصنف العملة الوظيفية صراحةً مع لقطة الأسعار.

## حماية المراجع

ربط الوحدة بأي صنف، حتى المعطل، يمنع تغيير رمزها أو رمزها القياسي أو دقتها. الصنف الفعال يمنع تعطيل وحداته ومجموعته. استخدام المجموعة أو أحد أبنائها في صنف يمنع تغيير رمزها أو أبها أو حساباتها. البيانات الوصفية تبقى قابلة للتعديل. `GET /units/{id}/items` يعرض أصناف الوحدة بصفحات مع صلاحية قراءة لكل الفروع. قائمة الأصناف تقبل groupId لعرض أصناف المجموعة المباشرة.

وجود سعر بيع في أي صنف يمنع تغيير العملة الوظيفية قبل تنفيذ تحويل أسعار معتمد، حتى دون قيد أو سعر صرف. لا يوجد حذف بطاقة؛ التعطيل يحافظ على الباركود والتاريخ. تفعيل الصنف يعيد التحقق من مراجع المجموعة والوحدات.

يمكن حاليًا تعديل وحدة الصنف الأساسية ونوعه وتتبعِه ومعاملاته لأن دفتر الحركات لم ينفذ. **قبل تمكين أي حركة أو فاتورة مخزنية يجب إضافة مراجع الاستخدام وقفل هذه البنية بعد الاستخدام، وتثبيت نسخ الوحدات والأسعار في المستندات**. لا يدعي هذا التنفيذ حفظ تاريخ مخزون غير موجود. مرجع الضريبة والدفعات والتسلسل التشغيلي واستعلام استخدام المستندات متبقية.

## الترقية والتحقق

طبّق 001 إلى [010_items_and_units.sql](../../backend/database/010_items_and_units.sql) بالترتيب ثم runtime-role.sql؛ جاهزية API تتطلب الإصدار 10. يضيف دور التشغيل حذف سطور ItemUnits اللازمة لاستبدال وحدات البطاقة، مع بقاء الجداول الأخرى وسجل التدقيق محمية. قيود SQL تحمي الشركة وتفرد الباركود والمعامل والخدمة، وفحوص EF تمنع تعديل سطور منفصلة عن البطاقة وإصدارها.

الاختبارات في [ItemTests.cs](../../backend/tests/Ameen.Erp.Tests/ItemTests.cs) و[ItemSqlIntegration.cs](../../backend/tests/Ameen.Erp.Tests/ItemSqlIntegration.cs)، وترقية المخطط والمضيف الفعلي. تغطي إعادة الطلب واستبدال السطور والتراجع، وتنافس الباركود، ودور التشغيل، وعزل الشركات، والدقة ورفض التقريب، والقراءة والتدقيق. لا يوجد اختبار حمل إنتاجي أو اكتمال دورة مخزون.
