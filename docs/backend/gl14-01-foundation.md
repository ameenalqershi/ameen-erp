# GL14-01 — أساس أنواع القيود والمستندات (2 نوفمبر 2026)

المرجع الوحيد: `muhaseb-erp-analysis/docs/modules/GL.md`، شاشة GL14، و`data/fields.csv` (F01–F13). **هذه دفعة بنية بيانات جزئية، وليست تنفيذًا مقبولًا لشاشة GL14 أو مهمة GL14-01 بكامل اعتمادياتها.**

## ما أُضيف

- `JournalDocumentType`: الشركة، الفرع الاختياري، الحالة، رمز نصي يحتفظ بالأصفار، الاسم Unicode، المصدر `Manual/Automatic`، مرجع سلسلة الترقيم، مرجع مسار الاعتماد، إلزام المرفق، المنشئ والتوقيت وإصدار تعديل صحيح. لا تُنشأ بطاقة تلقائية.
- SQL `027_journal_document_types.sql`: جدول جديد فارغ، مفتاح مركب للشركة والهوية، تفرد الرمز داخل الشركة، FK للشركة والفرع وسلسلة الترقيم ضمن الشركة، وضوابط مصدر النوع وإصدار التدقيق؛ مع قفل ترقية وtransaction وإعادة تطبيق آمنة. لا تعديل لأي قيد أو مستند أو مصدر مالي سابق.
- نموذج EF بنفس الأعمدة والقيود؛ فحوص نطاق الحقول ومصدر النوع وتاريخ التعديل، واختبارات منع التحايل.
- **حارس صريح في EF** يرفض حفظ/تعديل/حذف أي بطاقة GL14 حتى يوجد مسار اعتماد SYS09 فعلي ويمكن التحقق من وجوده وفعاليته ونطاقه. لا يوجد API لإنشاء أو استخدام الأنواع الآن؛ لا يربط النوع باليومية أو يتيح انتحال مصدر آلي.

## لماذا لم تُفعّل الوظيفة

المخطط الأصلي يلزم مرجع مسار اعتماد **موجود وفعال**. `SYS09` لا يملك حتى الآن كيانًا دائمًا للمسارات أو سياسات التدرج/الحدود. تخزين GUID شكلي بوصفه اعتمادًا صالحًا سيكون مخالفة للمخطط. لذلك `ApprovalRouteId` مطلوب في بنية GL14، لكن FK والتحقق الفعلي منه وفتح أوامر الحفظ معلقة حتى تنفيذ الحد الأدنى الصحيح من SYS09؛ لا تُختلق قيم افتراضية أو سياسة مالية.

يبقى ربط `GL03` بالنوع، والتحقق من سلسلة الترقيم النشطة وملاءمة نوع المستند، وقفل استخدام نوع يدوي مع مصدر آلي، والفصل بين قيد العكس والمصدر، وعمليات البحث والحفظ والتعطيل والاستخدام والتدقيق، واختبارات HTTP/JWT/القبول الشامل **غير منفذ**.

## الاستئناف
