# بطاقة الشركة SYS01

تطبق هذه الدفعة حقول الملف والعنوان ودورة التعديل والتفعيل. تبقى الشاشة جزئية: مرجع الدول وقواعد إلزام التسجيل والعنوان حسب الاختصاص والتحويل التاريخي للعملة لم تنفذ. لا تمثل المدخلات تحققًا من صحة التسجيل لدى جهة رسمية.

## العقد

إنشاء الشركة بواسطة مسؤول المنصة يتطلب `id/code/name/countryCode/functionalCurrency/currencyScale/profile`. أصبح `profile` إلزاميًا؛ يجب تحديث العملاء الذين يستخدمون عقد الإنشاء السابق. يحتوي:

| الحقول | القاعدة |
|---|---|
| legalName، jurisdiction، city | نص إلزامي حتى 200 حرف |
| street | نص إلزامي حتى 300 حرف |
| fiscalYearStartsOn | تاريخ إلزامي yyyy-MM-dd |
| englishName، district | اختياري حتى 200 حرف |
| notes | اختياري حتى 2000 حرف |
| commercialRegistration، taxRegistration | اختياري حتى 64 حرفًا؛ نص يحفظ الأصفار البادئة |
| buildingNumber، postalCode، additionalNumber | اختياري حتى 32 حرفًا؛ نص |

الاختياري يقبل null؛ النص الفارغ مرفوض. رمز الدولة حرفان إنجليزيان ورمز العملة ثلاثة؛ لا توجد مطابقة مع سجل دول خارجي. حقول التسجيل والمبنى والبريد ذات شرط دولة في التحليل، لكنها حاليًا اختيارية حتى تنفيذ ملف الاختصاص. `isProfileComplete` يعني اكتمال الحقول الأساسية فقط.

`PUT /api/v1/companies/{companyId}` يستقبل `expectedVersion/code/name/countryCode/functionalCurrency/profile/reason`. يستبدل الملف الوارد ويزيل الاختياري إذا كانت قيمته null أو أغفل داخل profile. يؤخذ مقياس العملة من بطاقة العملة المختارة الفعالة؛ ليس حقلًا قابلًا للتمرير في التعديل. الاستجابة التفصيلية تعرض حقول الملف مباشرة ضمن Company، لا داخل profile. `Revision` عدد صحيح يبدأ من 1، بينما `Version` رمز GUID للتزامن. الإنشاء والتعديل وتغيير الحالة تحفظ لقطات التدقيق، ومنها معرف المنفذ والتوقيت.

كل كتابة تتطلب `Idempotency-Key`. التعديل والحالة يتطلبان عضوية فعالة بصلاحية `company.configure` لكل الفروع وسببًا وإصدارًا مطابقًا. لا تمنح صلاحية مسؤول المنصة حق تعديل شركة بلا عضوية. يظل رمز الشركة فريدًا عند تغييره.

## الضوابط

- يمكن تغيير العملة الوظيفية قبل وجود أي قيد أو سعر صرف أو قالب دوري. وجود قيد ملغى أو قالب معطل يمنع التغيير أيضًا. لا يجري تحويل أرصدة أو تغيير مبالغ تاريخية.
- بداية أول سنة مالية يجب أن تطابق تاريخ البطاقة. بعد تعريف السنوات يجب أن يطابق تاريخ البطاقة بداية أقدم سنة معرفة؛ لا يعاد تقسيم الفترات عند تحرير البطاقة.
- `POST /api/v1/companies/{companyId}/status` يستقبل `expectedVersion/isActive/reason`. تعطيل الشركة يمنع أوامر التشغيل والإعداد وإعادة الطلبات السابقة، مع إبقاء القراءة وفق الصلاحيات وتعديل ملف الشركة وتغيير حالتها. لا يخفي التعطيل القيود أو التقارير التاريخية.
- `GET .../usage` يتطلب قراءة لكل الفروع ويعرض أعداد الفروع والحسابات والعملات والسنوات والقيود والقوالب والأسعار. `canChangeFunctionalCurrency` يصف غياب المراجع المالية؛ ليس تصريحًا بالتعديل ولا بديلًا لإعادة التحقق أثناء الأمر.
- `GET .../profile-audit-events?offset=0&limit=50` يتطلب القراءة والتدقيق لكل الفروع ويعرض أحداث بطاقة الشركة فقط. مسار التدقيق العام يبقى منفصلًا.

الاسم القانوني والعنوان بيانات البطاقة الحالية؛ لم تنفذ بعد لقطات المستندات الضريبية المؤرخة. تغيير هذه البيانات لا يدعي تحديثًا قانونيًا لمستند تاريخي.

## ترقية البيانات والتحقق

طبّق السكربتات 001 إلى [006_company_profiles.sql](../../backend/database/006_company_profiles.sql) بالترتيب، ثم runtime-role.sql. التطبيق الحالي يتطلب أيضًا [ترقية الفروع 007](branches.md)، ولا يطبق API الترقية تلقائيًا. ترقية 006 ذرية وقابلة للإعادة؛ تحافظ على المعرف والرمز والعملة والمقياس وVersion. تبدأ Revision من 1 والحالة فعالة، وتستنتج بداية السنة من أقدم سنة موجودة إن وجدت. تبقى البيانات القانونية والعنوان غير المعروفين null.

الشركة القديمة الناقصة تقرأ وفق الصلاحيات، لكن أوامرها تتوقف برمز `company_profile_incomplete` حتى يستكمل مسؤولها الملف عبر PUT. يجب تضمين استكمال الملف في خطة الانتقال قبل إعادة التشغيل. لا تملأ الترقية بيانات قانونية افتراضية.

الأدلة في [CompanyTests.cs](../../backend/tests/Ameen.Erp.Tests/CompanyTests.cs)، و[CompanySqlIntegration.cs](../../backend/tests/Ameen.Erp.Tests/CompanySqlIntegration.cs)، واختبارات ترقية المخطط والمضيف الفعلي. التحقق يشمل SQL وHTTPS وJWT والتزامن والتراجع عند فشل التدقيق؛ نتائج الحزمة في [سجل التحقق](validation.md).
