# INV01 — المخازن والمواقع

تنفذ هذه الدفعة بطاقة WAREHOUSE وربطها بالفرع ومواقع التخزين، وفق حقول INV01-F01..F18 وخريطة module-INV وعلاقة BRANCH→WAREHOUSE في data-model. تبقى الشاشة جزئية: عرض الاستخدام المستندي ودفتر المخزون ومتـاح البيع ونطاق صلاحيات المخزن المستقل غير منفذة. التحليل لا يحدد قائمة نوع المخزن ولا مرجع أمينه؛ القائمتان أدناه نطاق أولي معلن، وليستا إثباتًا لتطابق منتج خارجي.

## العقد والضوابط

| الحقل | العقد الحالي |
|---|---|
| المعرف والشركة | مولدان/محددان من سياق الأمر؛ مراجع SQL مركبة تمنع الربط بين الشركات |
| الرمز والاسم | Code حتى 32، لاتيني/رقمي موحد بأحرف كبيرة مع حفظ الأصفار؛ فريد في الشركة؛ Name حتى 200 |
| الإنجليزي والملاحظات | EnglishName حتى 200 وNotes حتى 2000، اختياريان |
| الفرع | BranchId إلزامي، فعال ومكتمل المدينة والعنوان |
| أمين المخزن | KeeperMembershipId إلزامي؛ عضوية ERP فعالة تسمح بفرع المخزن؛ ليس سجل موظف HR ولا يمنح تعيينه صلاحيات جديدة |
| النوع | Standard أو Quarantine فقط كتصنيف أولي مستنتج من قاعدة العزل؛ لا قائمة أنواع تجارية نهائية |
| حساب المخزون | InventoryAccountId إلزامي؛ أصل تفصيلي فعال ورقابي؛ لا يسمح بحركة يدوية عليه |
| تتبع الرف | TrackLocations منطقية صريحة؛ true يتطلب موقعًا واحدًا على الأقل، false يتطلب مصفوفة فارغة |
| المواقع | Locations مصفوفة مطلوبة، حتى 500؛ Code حتى 32 فريد داخل المخزن، Description إلزامي حتى 500 |
| الحالة والتزامن | بطاقة جديدة فعالة؛ Revision يبدأ 1 ويزداد عند التعديل أو تغيير الحالة؛ ExpectedVersion رمز GUID مستقل |
| التدقيق | actor ووقت الخادم وbefore/after وسبب التعديل والحالة؛ سجل كامل يشمل المواقع |

طلب التعديل يستبدل المواقع بالكامل ويعيد إنشاء هوياتها حاليًا؛ لا توجد حركات تعتمدها بعد. قبل إضافة أي مرجع مستندي للمواقع يجب حفظ هويتها أو منع استبدال المستخدم منها، وقفل بنية المخزن المستخدمة وفق سياسة موثقة. لا تجعل حركة مستقبلية تشير إلى موقع قابل للاستبدال بهذه الآلية.

لا حساب متاح بيع في هذه الدفعة؛ لا يفيد وجود Quarantine وحده أن قاعدة استبعاده من المتاح نُفذت. يجب على دفتر المخزون والحجز المستقبلي استبعاده صراحة والتحقق من حالة المخزن والفرع والمراجع عند كل أمر، مع اختبارات. لا يوجد ترحيل إلى حساب المخزن ولا قرار أولوية بينه وبين حساب مجموعة الصنف.

## الواجهات

البادئة `/api/v1/companies/{companyId}`:

| الطريقة والمسار | الوظيفة |
|---|---|
| POST /warehouses | إنشاء البطاقة ومواقعها |
| GET /warehouses | بحث search، فرع branchId، حالة isActive، صفحات offset/limit |
| GET /warehouses/{id} | البطاقة والمواقع |
| PUT /warehouses/{id} | تعديل كامل بإصدار متوقع وسبب |
| POST /warehouses/{id}/status | تعطيل/تفعيل بإصدار متوقع وسبب |
| GET /warehouses/{id}/audit-events | أحداث البطاقة بصفحات |
| GET /accounts/{id}/warehouses | المخازن المرتبطة بالحساب، بما فيها المعطلة |

الكتابة تتطلب `company.configure` على جميع الفروع، وIdempotency-Key. القراءة والبحث يتطلبان `ledger.read` ويقيدان بالفرع المصرح؛ إجمالي البحث لا يكشف مخازن الفروع المحجوبة. التدقيق يحتاج `audit.read` ونطاق جميع الفروع، وقراءة مراجع الحساب تتطلب ledger.read على جميع الفروع. حدود الصفحة 1..200، الإزاحة 0..1000000، وترتيب Code ثم Id. الحقول غير المعروفة والمفقودة الإلزامية مرفوضة وفق عقد JSON العام.

توحيد الرمز ضمن الشركة يمنع التكرار بين فروعها. عمليات إنشاء/تعديل البطاقة متسلسلة بقفل الشركة، وذرية مع تدقيقها وإيصال إعادة الطلب. يعاد التحقق من العضوية الحالية قبل إعادة الإيصال.

## حماية المراجع وسحب الصلاحيات

- أي مخزن، حتى المعطل، يقفل بنية حسابه وأجداده ورمز/شجرة فرعه وأجداده. ملخص استخدام الحساب يشمل القفل، والمسار `/accounts/{id}/warehouses` يبين المرجع المباشر.
- مخزن فعال يمنع تعطيل الحساب المرتبط أو الفرع. المخزن المعطل يسمح بتعطيل المرجع، لكن إعادة تفعيله تتطلب مراجع فعالة وصحيحة.
- لا يمنع ربط الأمين سحب عضويته أو تضييق صلاحياته؛ السحب الأمني يبقى ممكنًا. إعادة تفعيل أو تعديل المخزن يعيد التحقق من الأمين. المخزن لا يتعطل تلقائيًا عند سحب العضوية؛ قبل تمكين الحركات يجب إعادة التحقق من المرجع في كل أمر تشغيلي.
- حقل BranchUsage.HasSubtreeFinancialUsage ذو الاسم السابق يشمل الآن مرجع المخزن لأغراض قفل البنية، ولو لم يوجد قيد مالي. أعداد القيود في الملخص لا تتحول إلى أعداد مخازن.

## الترقية والتحقق

الترقية `011_warehouses.sql` تنشئ Warehouses وWarehouseLocations فارغين، بمفاتيح الشركة والفرع والأمين والحساب وقيود النوع والإصدار وتفرد الرمز. لا تختلق مخازن لشركة قديمة. حدّث دور التشغيل بعد الترقية؛ استبدال المواقع يتطلب DELETE على WarehouseLocations. الجاهزية تتطلب SchemaVersion 11.

اختبارات WarehouseTests تغطي البطاقة والمواقع والفرع والأمين والحساب والقفل والصلاحيات والعزل وإعادة الطلب والتراجع. WarehouseSqlIntegration يختبر اتصالات متزامنة واستبدال المواقع وفشل التدقيق ودور التشغيل ورفض مرجع فرع من شركة أخرى. SchemaUpgradeIntegration يحقن فشل DDL ويثبت التراجع ثم إعادة تطبيق 011؛ HostedApiIntegration يختبر البطاقة ومواقعها وبحثها وحالتها وتدقيقها على HTTPS/JWT/SQL.

لا يثبت ذلك حركات أو أرصدة أو تكلفة أو عزل متاح بيع أو اختبارات حمل. التصنيف ومرجع الأمين مميزان partial في مصفوفة الحقول.
