# INV05 — الدفعات والأرقام التسلسلية (تنفيذ جزئي)

مرجع التنفيذ: `muhaseb-erp-analysis/docs/modules/INV.md`، الشاشة INV05. الدفعة الحالية تؤسس بطاقة الهوية فقط؛ لا كمية أو تكلفة أو ضمان أو حركة مخزون ناتجة عن حفظها.

المساران تحت `/companies/{companyId}/items/{itemId}` هما `/lots` و`/serials`. لكل منهما POST إنشاء وGET بحث، وGET/PUT `/{id}`، وPOST `/{id}/status`، وGET `/{id}/audit-events`. البحث يدعم search وqualityStatus وisActive وoffset/limit. الكتابة تتطلب Configure شامل الشركة ومفتاح Idempotency-Key، والتعديل والحالة ExpectedVersion وReason. القراءة تتطلب Read؛ سجل التغييرات يتطلب Audit شامل الشركة وRead.

تتحقق الخدمة من الصنف الفعال ونوع تتبعه ونطاق الشركة. الصلاحية بعد الإنتاج حصراً عند وجودهما؛ وجود ShelfLifeDays يتطلب تاريخ انتهاء، دون اشتقاق تاريخ تلقائي. يحجز الرمز حتى بعد التعطيل، وتفرده في نطاق الشركة والصنف ونوع التتبع. يطبّع Check.Code الرمز إلى أحرف كبيرة ويقيد طوله إلى 32. لا يمكن تغيير نوع تتبع الصنف بعد إنشاء أي هوية له، ولا فرض مدة صلاحية على صنف له هوية بلا انتهاء.

كل تعديل ذري مع التدقيق وإيصال الطلب، وتزيد Revision مع تغيير Version. يضم مفتاح العملية الصنف والهوية لمنع إعادة إيصال عبر مسار مختلف. يتراجع الحفظ عند فشل التدقيق. المخطط 012 يضيف InventoryIdentities بمرجع مركب للشركة والصنف، وفهارس التفرد والبحث، وقيود التاريخ والحالة والإصدار؛ يشترط تطبيق 011 أولاً.

## حدود تحتاج الاستكمال

- Code موحد مؤقتاً مع رقم الدفعة/التسلسل. F03 وF09/F10 جزئية: التحليل يعرض حقولاً مستقلة. يجب فصل رمز البطاقة ورقم الهوية قبل إعلان مطابقة الشاشة، مع ترقية بيانات واضحة وعقد توافق.
- حالات Available/Quarantine/Rejected نطاق أولي مستنتج، وليست قائمة معتمدة من التحليل الذي لم يسم قيمها. لا تطبق هذه الحالات حجزاً أو إتاحة في دفتر مخزون غير منفذ.
- إلزام الصلاحية مستنتج من ShelfLifeDays؛ F12 جزئي حتى حسم سياسة الشاشة النهائية.
- F14/F15/F17 تستخرج من أحداث التدقيق وليست حقولاً مباشرة في استجابة البطاقة.
- عرض الاستخدام، الضمان، ربط الهوية بمستندات INV07، قواعد كمية التسلسل وحركته بين المخازن وإقفال هويته عند الاستخدام غير منفذة. يجب إضافة حماية الهوية قبل إطلاق أي حركة تعتمد عليها.
- تعطيل الصنف يمنع أوامر البطاقة بما فيها تعطيل الهوية حالياً؛ لا يمنع قراءة تاريخها.

## التحقق

InventoryIdentityTests تغطي الحفظ والبحث والتدقيق والتواريخ والسياسة والصلاحية والتكرار والإصدار والتراجع. InventoryIdentitySqlIntegration تغطي إعادة الطلب المتزامن، سباق التفرد، البحث المترجم، التراجع عند فشل التدقيق وإعادة المحاولة وقيود التاريخ والمرجع. SchemaUpgradeIntegration يطبق 012 مرتين ويتحقق من عدم إنشاء بيانات افتراضية. HostedApiIntegration يغطي دورة بطاقة الدفعة والبحث والتدقيق وعزل مسار التسلسل عبر HTTPS/JWT/SQL.
