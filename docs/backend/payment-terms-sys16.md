# SYS16 — أساس بيانات وسائل الدفع والأقساط (مرحلة البنية)

المصدر الحاكم: muhaseb-erp-analysis/docs/modules/SYS.md (SYS16) وdata/fields.csv، دون تعديلهما.

## النطاق المنفذ

- بنية PaymentTerms وPaymentTermLines بترقية SQL **033** ذرية، آمنة لإعادة التنفيذ، تابعة للإصدار 032؛ لا تُعدل الشركات أو المدفوعات التاريخية.
- العلاقات CompanyId ومرجع فرع اختياري وحساب تسوية اختياري ضمن الشركة نفسها؛ رمز طريقة فريد داخل الشركة؛ نوع الوسيلة (Cash/Card/Credit المذكورة في غرض SYS16) واسم Unicode وأيام سماح وإصدار عددي وتوقيت تدقيق.
- خطة دفعات متسلسلة بنسب دقيقة من صفر إلى 100 (غير شاملة للصفر) وأيام من تاريخ الأساس غير سالبة. إذا أُدخلت خطة، يرفض الـDomain أي مجموع ليس **100% بالضبط**؛ خريطة EF تحفظ decimal(9,6). لا تُفترض حدود عملية إضافية لعدد الأقساط أو طلب حساب تسوية لصنف معين.
- سلامة المفاتيح المركبة للفرع والحساب وبنود البطاقة، وفهارس فريدة، وقيود SQL، ومصداقية النسخ القديمة عند فشل الترقية وإعادتها. اختبارات PaymentTermSqlIntegration تستعمل قاعدة اختبار مؤقتة فقط.

## حدود السلامة

هذه **مرحلة SYS16-01 البنيوية** وليست بطاقة دفع قابلة للحفظ عبر REST؛ يمنع ErpDbContext.ValidateChanges كل إضافة/تعديل/حذف للبطاقة أو بنودها بالخطأ payment_term_policy_unavailable حتى تُعتمد واجهات SYS16-02، ومراجعات الصلاحيات والتكامل مع SAL06/PUR07/POS03. فحص قيمة Card **لا** ينشئ سند نقدي، ولا يرحل إلى صندوق أو دفتر الأستاذ، ولا يثبت حالة تسوية. لا توجد سياسة إضافية لبلدان/عملات البطاقات أو لحساب التسوية المشروط، وقائمة أنواع الوسيلة المعتمدة للواجهة يمكن أن توسع نموذج البيانات مستقبلًا.

## أدلة القبول

- PaymentTermFoundationTests.cs: القيم المطلوبة، الجدول 100%، رفض الخطة غير المتزنة/النسبة الصفرية/الأيام السالبة، حفاظ رقم الإصدار والوقت، عدم توليد سند قبض.
- PaymentTermSqlIntegration.cs: فشل ترقية منتصف DDL مع rollback وإعادة تشغيل متكرر دون تكرار، أعمدة SYS16-F01..F14، مفاتيح مركبة بالشركة، رفض تعديلات SQL غير صالحة، وبوابة EF المغلقة.
- backend/scripts/traceability.py --check مع backend/scripts/progress.py --check: الحقول **partial** بنيويًا فقط؛ لا علامة implemented حتى إضافة API وJWT وصلاحيات التشغيل.

## فحص تعارض ترقيم الهجرات بين الفروع

يحظر تشغيل SYS16 033 على قاعدة تحمل بالفعل SchemaVersion=33 إذا لم تكن جداول SYS16 موجودة: THROW 51002 صريح بدل التخطي الصامت، مع اختبار SQL على قاعدة مؤقتة يثبت عدم إنشاء جداول أو عبث بنسخة أخرى. يتطلب الدمج مع CASH PR #69 ترتيبًا جديدًا: CASH 033/034 أولًا، ثم نقل SYS16 إلى 035 وفحص CI حقيقي قبل إتاحة الترحيل للإنتاج. هذه الحماية لا تُحل التعارض وحدها، وPR دمج SYS إلى main يبقى draft.
