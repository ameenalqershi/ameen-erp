# GL06-GP02 — السجل الدائم للدفعات (مراجعة 28 أكتوبر 2026)

## العقد

تمت مقارنة الحقول أصلًا مع `muhaseb-erp-analysis/docs/modules/GL.md` و`muhaseb-erp-analysis/data/fields.csv`. يستخدم `GL06-F10` هوية منفذ الدفعة `ActorId` من JWT، و`F11` وقت الخادم `CreatedAt`، و`F12` `Revision` عددًا صحيحًا متزايدًا، و`F13` `LastModifiedAt` وقت خادم. يبقى `Version` UUID منفصلًا لقفل التزامن وليس بديلًا عن `Revision`. تظل خانة نوع المصدر `GL06-F04` جزئية لغياب بقية الدفاتر.

- `POST /api/v1/companies/{companyId}/journals/process-batch` يقبل `{"action":"post","items":[{"journalId":"...","expectedVersion":"...","idempotencyKey":"..."}],"batchKey":"your-stable-unique-key"}`. `batchKey` اختياري لحفظ التوافق؛ إذا حذف تبقى المعالجة السابقة دون رأس دائم.
- `GET /api/v1/companies/{companyId}/journals/processing-batches/by-key/{batchKey}` يعيد `batchId` و`version` و`revision` و`createdAt` و`finishedAt` والنتائج. يشترط نفس هوية المنشئ وصلاحية قراءة القيود ضمن الشركة والفرع.
- يحفظ نجاح كل مستند ورفض التحقق وخطأ قاعدة البيانات في نتائج الدفعة. المستند له معاملة ترحيل مستقلة؛ سجل التشخيص يكتب في معاملة أخرى، وتظل جميع محاولاته في سجل التدقيق غير القابل للتعديل. عند فشل تخزين النتيجة بعد ترحيل مستند، يعيد مفتاح المستند القديم إيصالًا واحدًا في الاستئناف دون تكرار أثره.
- لا يُعاد المستند الذي اكتمل بنجاح أو سجل رفض تحقق نهائيًا تحت المفتاح نفسه؛ يسمح بإعادة المحاولة بعد خطأ تقني ويزيد إصدار الدفعة. ترفض إعادة استخدام مفتاح الدفعة بحمولة أو هوية أخرى.

## حماية قاعدة البيانات واختبارات القبول

ترقية `025_journal_processing_batches.sql` ذرية وقابلة للإعادة دون تعديل القيود أو إنشاء دفعات تاريخية مصطنعة. يُختبر رفض DDL في منتصف الترقية، ثم التشغيل مرتين؛ SQL يتسبب عمدًا بفشل Outbox لقيد واحد، ويسجل خطأه بينما يُرحّل الآخر، ثم يزيل سبب الفشل ويعيد المحاولة، ويؤكد أن أثر الناجح لم يُكرر وأن إصدار الرأس أصبح 4 مع ثلاث محاولات تدقيق. اختبار HTTPS/JWT يسترجع رأس الدفعة والنتائج. الدليل: [CI 321/321](https://github.com/ameenalqershi/ameen-erp/actions/runs/40738969586).

## الاعتماديات المفتوحة

لا ينفذ هذا التغيير توجيه مصادر خارج GL، أو عامل توزيع Outbox خارج قاعدة البيانات (GL06-GP01)، أو مراحل مراجعة SYS09، أو بنود الطباعة. تظل الشاشة GL06 جزئية. لا يُعد حفظ خطأ تقني ضمانًا إذا كانت قاعدة البيانات نفسها غير متاحة تمامًا وقت كتابة سجل النتائج؛ يلزم تشغيل ومراقبة خارجيان لهذه الحالة.
