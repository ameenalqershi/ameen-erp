# أسعار الصرف SYS05 ومعاينة إقفال الأستاذ GL11

هذه الدفعة تضيف استعلامات تاريخ أسعار الصرف ومعاينة موانع إقفال فترة الأستاذ. تبقى أنواع الأسعار وقيمها ونطاقها حسب الفرع وتعطيل السعر وإصداره العددي غير منفذة. كذلك لا تنفذ مطابقة دفاتر الذمم والبنوك والمخزون والضرائب والأصول أو قيد إقفال السنة. لا يمثل نجاح معاينة الأستاذ جاهزية لإقفال ERP كامل.

## أسعار الصرف

المسارات تحت `/api/v1/companies/{companyId}/exchange-rates`؛ قراءة الأسعار المشتركة للشركة تتطلب `ledger.read`، والإنشاء يتطلب `company.configure` لكل الفروع ومفتاح إعادة الطلب.

| المسار | السلوك |
|---|---|
| GET /search | صفحات مع currencyCode وfrom وto وsource وoffset وlimit؛ التاريخ شامل للطرفين والمصدر بحث جزئي |
| GET /quote?currencyCode=USD&date=2026-10-20 | أحدث سعر سريان لا يتجاوز التاريخ المطلوب مع العملة الوظيفية والمصدر والاتجاه |
| GET /{id} | كائن rate التاريخي مع functionalCurrency |
| GET /{id}/usage | القيود المرتبطة بالسعر، مرة واحدة لكل قيد؛ قراءة لكل الفروع |
| GET /{id}/audit-events | أحداث إنشاء السعر؛ قراءة وتدقيق لكل الفروع |

الاتجاه هو عدد وحدات العملة الوظيفية مقابل وحدة واحدة من عملة المصدر؛ الضرب في `rateToFunctional` يحول المبلغ إلى العملة الوظيفية. الأسعار عشرية دقيقة في JSON بصيغة نص. لا يعكس المسار السعر تلقائيًا، ولا يعتمد على سعر مستقبلي. العملة الوظيفية تعيد واحدًا مع exchangeRateId/effectiveDate/source بقيم null وisFunctionalCurrency=true؛ لا ينشأ سجل سعر صوري.

عرض السعر يرفض العملة المعطلة أو غير المعرفة وغياب سعر نافذ. يبقى البحث والبطاقة التاريخية والاستخدام متاحًا للقراءة عند تعطيل العملة. السعر المعروض اقتراح بتاريخ محدد؛ لا يحجزه الاستعلام، وقد يضاف سعر أحدث قبل إنشاء القيد. إنشاء أو تعديل سطور القيد يتحقق مجددًا من أحدث سعر نافذ. السعر المحفوظ في مستند سابق لا يتغير بسبب سعر لاحق، والعكس يحتفظ بنسخته التاريخية.

يعرض الاستخدام جميع حالات القيود، بما فيها الملغى والعكس، مع صفحات؛ القالب الدوري لا يخزن مرجع سعر حتى التوليد، لذلك يظهر القيد الناتج ضمن الاستخدام. سجل الإنشاء الجديد يحفظ المصدر والعملة الوظيفية أيضًا؛ الأحداث القديمة قد تفتقر لهما. لا توجد عملية تعديل أو حذف للسعر، وتبقى حماية EF ودور SQL للجدول غير القابل للتعديل كما كانت. الرقم GUID هو Version تقني وليس رقم إصدار تعديل عدديًا؛ صححت مصفوفة المطابقة لعدم مساواتهما.

## معاينة الإقفال

`GET /api/v1/companies/{companyId}/periods/{id}/close-preview?offset=0&limit=50` يتطلب `period.close` و`ledger.read` على كل الفروع. النتيجة تشمل:

- expectedVersion للفترة وcheckedAt من الخادم.
- generalLedgerOnly=true، وcanCloseGeneralLedger لنتيجة الفحوص الحالية.
- checks: حالة الشركة، اكتمال ملفها، كون الفترة مفتوحة، غياب القيود المعلقة، واتزان القيود المرحلة.
- عدد القيود المرحلة والمعلقة، وissues بصفحات تتضمن معرف القيد وفرعه ورقمه وحالته وسبب المنع.

المعلقة هي Draft وSubmitted وApproved. المرحّلة تشمل Posted وReversed؛ الملغاة لا تمنع الإقفال. فحص الاتزان يستدعي قاعدة القيد نفسها المستخدمة في التنفيذ، فلا يكتفي باتزان إجمالي الفترة الذي قد يخفي قيودًا غير متزنة متعاكسة.

الاستعلام لا يكتب تدقيقًا أو إيصالًا ولا يقفل الفترة ولا يحجز صلاحية المعاينة. عند التنفيذ عبر POST /periods/{id}/close يعاد فحص الإصدار والصلاحية وحالة الشركة والقيود واتزان المرحّل داخل معاملة الشركة. قد تنجح المعاينة ثم يمنع قيد جديد الإقفال؛ يجب عرض نتيجة التنفيذ للمستخدم. لا يعد تغيير البيانات المتزامن خطأ في المعاينة السابقة، وcheckedAt ليس ضمان لقطة معاملات عبر جميع الاستعلامات.

الفحوص المشتركة بين المعاينة والتنفيذ تخص الأستاذ فقط؛ لا تمنح حق اعتماد أو تنفيذ أو وصول لفروع إضافية. لا يحتاج هذا الامتداد ترقية SQL جديدة؛ يبقى إصدار المخطط 7.

الأدلة في [RateAndCloseTests.cs](../../backend/tests/Ameen.Erp.Tests/RateAndCloseTests.cs) واختبارات المضيف الفعلي وSQL. تغطي الاختبارات السعر التاريخي وحدود السريان والعملات المعطلة والدقة والاستعمال والصلاحيات، والموانع والإقفال والتغير بعد المعاينة؛ اختبار SQL القائم للتزامن بين الترحيل والإقفال يستمر ضمن الحزمة.
