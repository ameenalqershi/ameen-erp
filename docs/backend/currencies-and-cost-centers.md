# SYS04 وCOST01 — عقود التهيئة

المصدر هو حقول الشاشتين وقواعدهما في حزمة التحليل الأصلية، مع المحافظة على عزل الشركة والفروع وذرية التعديل والتدقيق وإيصال الطلب. هذه توسعة لأساس التهيئة، وليست إعلان اكتمال ERP أو وحدة التكاليف.

## العملات SYS04

الجذر `C=/api/v1/companies/{companyId}/currencies`.

| الطريقة | المسار | النتيجة |
|---|---|---|
| GET / POST | C | القائمة الحالية / CreateCurrencyRequest |
| GET | C/search | Page&lt;Currency&gt;؛ search وisActive وoffset وlimit |
| GET / PUT | C/{id} | Currency / EditCurrencyRequest |
| POST | C/{id}/status | SetCurrencyStatusRequest |
| GET | C/{id}/usage | أعداد الحسابات والأسعار والقيود والقوالب، وبيان أنها عملة وظيفية |
| GET | C/{id}/audit-events | Page&lt;AuditEvent&gt; للإنشاء والتحرير وتغيير الحالة |

إنشاء العملة يتطلب `code` و`scale` و`name` صراحة. الاسم الإنجليزي والملاحظات ورمز العرض واسم الجزء اختياريون. يلزم تحديث أي عميل قديم كان يرسل الرمز والدقة فقط. الرمز الداخلي هو رمز العملة نفسه من ثلاثة أحرف لاتينية، ولا يعاد ترميزه بعد الإنشاء لأن المراجع تستخدمه. التحقق الحالي لشكل الرمز؛ لم يربط بقائمة ISO 4217 خارجية معتمدة.

```json
{
  "code": "USD", "scale": 2, "name": "دولار أمريكي",
  "englishName": "US dollar", "notes": null,
  "displaySymbol": "$", "fractionName": "سنت"
}
```

الاسمان حتى 200 حرف، والملاحظات 2000، ورمز العرض 20، واسم الجزء 100. null يفرغ النص الاختياري، والنص الفارغ ومحارف التحكم مرفوضة. PUT يتطلب expectedVersion/scale/name/englishName/notes/displaySymbol/fractionName/reason. الحالة تعدل بعقد مستقل: expectedVersion/isActive/reason. Revision عدد صحيح يبدأ من 1 ويزداد عند الحفظ؛ Version رمز التزامن المستقل.

دقة العملة الأجنبية غير المستخدمة قابلة للتعديل بين 0 و6. وجود حساب مقيد بعملتها أو سعر صرف أو قيد بأي حالة أو قالب حالي يمنع تغييرها؛ لذلك لا يعاد تفسير مبلغ سابق بدقة جديدة. دقة العملة الوظيفية مقفلة هنا لتجنب اختلافها عن Company.CurrencyScale. تحويل العملة الوظيفية أو الدقة التاريخية ليس منفذًا.

تعطيل العملة الوظيفية ممنوع. تعطيل الأجنبية يمنع أسعارًا وحسابات وقيودًا وقوالب جديدة بها، ويعاد فحصه عند تقديم القيد واعتماده وترحيله وتوليد القالب. يظل الأثر المرحل ظاهرًا في التقارير. يمكن إعداد مسودة عكس تاريخية، لكنها تحتاج تفعيل العملة قبل تقديمها وترحيلها؛ لا تعاد حسابات أسعارها التاريخية. إلغاء المسودة وإعادتها لا يتطلبان عملة فعالة.

كل الأوامر تتطلب company.configure على جميع الفروع. القراءة الأساسية تتطلب ledger.read، والاستخدام يتطلب نطاق جميع الفروع لأن أعداده تشملها. التدقيق يتطلب ledger.read وaudit.read على جميع الفروع. إعادة Idempotency-Key تعيد الإيصال بعد التحقق من الصلاحية؛ لا تزيد Revision ولا تضاعف التدقيق.

## مراكز التكلفة COST01

الجذر `C=/api/v1/companies/{companyId}/cost-centers`، والمسارات GET/POST وGET/PUT {id} وPOST {id}/status وGET {id}/usage وGET {id}/audit-events، وبحث GET search. تبقى القائمة الأصلية قائمة بسيطة؛ المسار search يضيف الصفحات ومرشحات search/branchId/parentId/isActive.

```json
{
  "code": "001", "name": "مركز المبيعات", "branchId": null,
  "parentId": null, "responsibleMembershipId": null,
  "englishName": "Sales center", "notes": null
}
```

الأسماء والملاحظات وحدودها مثل بطاقة الحساب. ParentId اختياري، والمرجع في الشركة نفسها. المسؤول مرجع إلى Membership داخل الشركة، يصل إلى هوية المستخدم عبر Subject؛ يجب أن تكون عضويته فعالة وتشمل الفرع، أو تشمل كل الفروع إذا كان المركز عامًا. تعديل الاسم لا يتوقف بسبب تعطيل المسؤول لاحقًا؛ تغيير المسؤول أو فرع المركز يعيد فحص المرجع.

- تمنع دورات الشجرة، ويجب أن تكون سلسلة الآباء فعالة عند إنشاء العلاقة أو تعديل البنية أو التفعيل.
- المركز العام يمكن أن يضم مراكز عامة ومراكز فروع. المركز التابع لفرع لا يضم مركزًا عامًا أو مركز فرع آخر. تضييق نطاق الأب لا يسمح بإخفاء أبناء من فروع أخرى.
- تغيير الرمز أو الأب أو الفرع ممنوع إذا كان المركز أو أحد أحفاده مستخدمًا في قيد بأي حالة أو قالب حالي، حتى المعطل. الأسماء والملاحظات والمسؤول قابلة للتحرير مع التدقيق.
- تعطيل الأب يتطلب تعطيل أبنائه الفعالين أولًا. لا يتاح حذف مركز، ولا يحذف تعطيله حركته. حالة المركز يعاد فحصها عند التقديم والاعتماد والترحيل؛ تظل التقارير التاريخية متاحة.
- البحث والتفاصيل يكشفان المراكز العامة ومراكز الفروع المصرح بها فقط. فلترة أب من فرع محجوب مرفوضة. المراكز العامة ليست وسيلة لتجاوز نطاق الفروع.

الاستخدام يعرض عدد الأبناء المباشرين وأعداد القيود والقوالب المباشرة وصفحة مراجعها، وعلم HasUsageInSubtree للمركز وشجرته. استعمال المراكز التابعة لا يخلط مع المراجع المباشرة. البحث لا يجمع أرصدة أحفاد المركز، وتقارير الأستاذ الحالية تصفي مركزًا محددًا فقط؛ موازنات COST02 وتوزيعات COST04 وتقارير COST05 لم تنفذ.

الأوامر تتطلب company.configure على جميع الفروع. الاستخدام العام يتطلب ledger.read على جميع الفروع، والتدقيق يتطلب معه audit.read. التدقيق يحفظ قبل/بعد وRevision وVersion والسبب والفاعل ووقت الخادم؛ الحقول الزمنية واسم المنشئ متاحة من الأحداث، وليست حقولًا مباشرة على البطاقة.

**COST01-F11 (نوع المركز) ما زال pending**: التحليل يصف enum دون قائمة قيم، وقد طُلب توضيحها من المستخدم. لا توجد قيمة مختلقة أو ادعاء أن هذا الحقل منفذ. بقية حقول البطاقة لا تعتمد على اختيار القائمة.

## الترقية والتحقق

طبّق السكربتات 001 إلى 005 بالترتيب، ثم runtime-role.sql. لقاعدة عند الإصدار 3 طبّق [004_currency_cards.sql](../../backend/database/004_currency_cards.sql) ثم [005_cost_center_hierarchy.sql](../../backend/database/005_cost_center_hierarchy.sql). API لا يطبق ترقية تلقائية، والتطبيق الحالي يتطلب أيضًا الإصدار 006 الموضح في [بطاقة الشركة](companies.md).

004 يبقي رمز العملة ودقتها وVersion كما هي، ويضع رمزها اسمًا ظاهرًا ابتدائيًا وRevision=1 وIsActive=true. العملة الوظيفية المنشأة تلقائيًا تستخدم الرمز اسمًا ابتدائيًا أيضًا ويستطيع مسؤول الإعداد تحريره. لا تعني هذه القيمة ترجمة عربية معتمدة. 005 يحافظ على بيانات المركز السابقة، ويضيف أبًا ومسؤولًا وحقول نص اختيارية null وRevision=1. البداية من 1 تعني بدء عد التعديلات بعد الترقية؛ لا تختلق تاريخ تعديل سابقًا. سجلات التدقيق القديمة تبقى بصيغتها، وقد تفتقر العملة الوظيفية المنشأة بإصدار قديم إلى حدث إنشاء مستقل.

كل ترقية ذرية وقابلة للإعادة، وتختبر الحزمة فشل DDL في منتصفها ثم التراجع والتطبيق مرتين. المراجع المركبة في SQL تمنع أبًا أو مسؤولًا من شركة أخرى. يشمل التحقق تزامن إعادة الطلب وفشل حفظ التدقيق والتراجع الكامل، والكتابة بدور قاعدة التشغيل وواجهات HTTPS/JWT الفعلية. الاستخدام الحالي يقرأ المراجع ذات الصلة إلى الذاكرة ولا يقدم ضمان snapshot عبر الاستعلامات أو إثبات أداء لأرشيف كبير.
