# Contribution and membership path | مسار المساهمة والعضوية

## Everyone is welcome

Any GitHub user can discover Issues, propose enhancements, fork code, and submit PRs to this public repository. You do not need to be on a GitHub team to contribute.

## Progression (not an automatic promotion)

| Stage | What you do | Privileges |
| --- | --- | --- |
| Explorer | Read docs and ask focused questions | Public contribution channels |
| Contributor | Submit scoped improvements and tests | Public PR/Issue participation |
| Recurring contributor | Maintain high-quality work and reviews | Recognition and potential review invitations |
| Invited maintainer | Help triage and review an agreed area | Explicitly granted repository permissions |
| Owner | Final licensing, access, security and release decisions | Repository administration |

**No guaranteed appointment:** GitHub organization/team membership and write access remain invite-only and depend on a sustained trusted track record, available maintainers, and project needs. Contributors retain attribution through commits.

## Good first tasks

The first task should have an isolated change, documented file references, prerequisites and a Definition of Done. Prefer verification of existing documented behavior to new accounting features with undefined policies.

## Review expectations

Explain why a change is correct, not merely that it builds. Include tests for rejection/unauthorized cases where relevant. Respect the project's Arabic-first documentation; bilingual improvements are welcome.
