# الدورات التشغيلية ومعايير القبول

المخططات المرئية وأصول Mermaid في `diagrams/`. السيناريوهات أدناه اختبارات قبول **لتنفيذ النظام مستقبلًا**؛ لم ينفذ برنامج محاسبي في هذه المرحلة. فحوص جودة حزمة التحليل منفصلة في `validation-report.json`.

## شراء إلى سداد

طلب شراء PUR04 → عروض PUR05 → أمر PUR06 → استلام INV07 → فاتورة PUR07 → مطابقة PUR10 → اعتماد وترحيل → جدولة PUR11 → سند CASH04 → تخصيص PUR11.

الشراء المباشر يمكن أن يبدأ بفاتورة تولد الاستلام مرة واحدة. الاستلام السابق يولد GRNI وتكلفة مؤقتة، ثم تسوي الفاتورة الفرق. التنفيذ الجزئي يتتبع الكمية على كل سطر؛ إلغاء المتبقي لا يلغي المستلم. رفض الجودة يعزل البضاعة، ومرتجع المورد PUR08 لا يمحو الفاتورة.

## بيع إلى تحصيل

عميل SAL01 → عرض SAL14 → أمر SAL04 → تحقق سعر وائتمان → حجز INV11 → تسليم SAL05 → فاتورة SAL06 → متطلبات إصدار الدولة TAX06 → قبض CASH03 → تخصيص SAL11 → متابعة SAL12.

إذا كان البيع مباشرًا فالفاتورة تنشئ الأثر المخزني مرة واحدة. إذا سبقها التسليم فتسحب الكمية المتاحة للفوترة دون صرف جديد. يسمح التسليم والفوترة والتحصيل الجزئي بروابط سطور ومبالغ. الرفض الضريبي لا يحذف أثر حركة مخزون مثبتة؛ يبقى مسار معالجة معلوم وفق حالة الإصدار.

## إقفال شهر وسنة

حصر مسودات ومعتمد غير مرحل → مطابقة بنوك وصندوق → مراجعة مخزون وGRNI والطريق → مطابقة العملاء والموردين والأصول → مصروفات ومستحقات وإهلاك → تقييم عملات → ضريبة → ميزان وقوائم → اعتماد إقفال.

السنة: اعتماد نتيجة الفترة النهائية ثم إقفال حسابات النتائج إلى الأرباح المرحلة وفق دليل الشركة. الدفاتر المستمرة لا تضاعف الأرصدة بقيود افتتاحية جديدة بلا سياسة واضحة. إعادة فتح سنة يستلزم معالجة قيد إقفالها وإعادة إصدار المطابقات والتقارير.

## تجربة قبول المحاسب

محاسب مستخدم للمتكامل ينفذ دون توجيه: إنشاء حساب فرعي، إضافة صنف ووحدته، فاتورة شراء، فاتورة بيع، قبض جزئي، مرتجع، كشف عميل، ميزان مراجعة. يسجل عدد الخطوات والحقول غير المفهومة والاختصارات المتوقعة. أي فرق يوثق في مصفوفة المطابقة، وتراجع التسمية والترتيب قبل اعتماد الواجهة.

التحقق من الملف التحليلي لا يساوي نجاح هذه الاختبارات على تطبيق فعلي.
