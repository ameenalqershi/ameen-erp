# نموذج البيانات والصلاحيات والتشغيل

## حدود الكيانات

المخطط `diagrams/source/data-model.mmd` نموذج مفاهيمي؛ ليس DDL نهائيًا. أسماء الكيانات في المخطط تقابل المفاهيم التالية:

| المجال | الكيانات والروابط | قيد مهم |
|---|---|---|
| المؤسسة | شركة ← فروع ← مخازن/صناديق؛ شركة ← سنوات ← فترات | كل حركة تشير إلى الشركة والفرع؛ لا اعتماد على اختيار الواجهة وحده |
| الحسابات | حساب أب/ابن؛ قيد ← سطور؛ سطر ← حساب ومركز ومشروع | الحساب التجميعي لا يستقبل سطورًا؛ الشجرة بلا دورات |
| الأطراف | طرف ← أدوار عميل/مورد؛ عناوين واتصالات وتسجيلات | الطرف قد يحمل الدورين؛ المقاصة تحتاج مستندًا واضحًا |
| الأصناف | صنف ← وحدات/باركود؛ دفعة؛ رقم تسلسلي؛ موضع تخزين | باركود فريد بحسب سياسة الشركة؛ تحويل الوحدة مثبت تاريخيًا |
| المستندات | رأس ← سطور؛ روابط مصدر/هدف بين السطور | مجموع الكمية المنفذة لا يتجاوز المسموح |
| الذمم | بند مفتوح ← تخصيصات تسوية ← حركة قبض/صرف/إشعار | حفظ القيمة الأصلية والمسددة والمفتوحة بالعملتين |
| المخزون | حركة ← طبقات تكلفة/تخصيص خروج؛ حجز مستقل | الرصيد نتيجة الحركات لا قيمة قابلة للتعديل اليدوي |
| الضرائب | قاعدة مؤرخة؛ لقطة ضريبة سطر؛ مستند إلكتروني؛ محاولات إرسال | هوية الإصدار ثابتة؛ محاولات متعددة لا فواتير جديدة |
| الأصول | أصل ← أحداث/إهلاك/استبعاد | أصل وفترة ودفتر إهلاك مفتاح يمنع التكرار |
| الرقابة | دور؛ صلاحية؛ نطاق بيانات؛ اعتماد؛ حدث تدقيق | المرفقات تخضع لنطاق المصدر؛ لا كشف عبر رابط مباشر |
| التكامل | Outbox؛ عملية استيراد؛ سطور أخطاء؛ مفاتيح Idempotency | إعادة المعالجة آمنة، ورسالة الفشل لا تكشف مفاتيح سرية |

## أدوار مقترحة

| الدور | الإنشاء | الاعتماد والترحيل | نطاق الاطلاع | القيود |
|---|---|---|---|---|
| مدير النظام | المستخدمون والتهيئة التقنية | إعداد مسارات الصلاحية | إعدادات التشغيل | لا يحصل تلقائيًا على اعتماد مالي |
| المحاسب | قيود وسندات وتسويات | حسب سقف التفويض | فروعه وحساباته | لا يفتح فترة ولا يتجاوز سقفًا ذاتيًا |
| رئيس الحسابات | المراجعات والتسويات | اعتماد وترحيل وإقفال ضمن التفويض | التقارير والدفاتر | لا يعتمد مستندًا أنشأه إذا فصل المهام إلزامي |
| أمين الصندوق | قبض وصرف وعهدة | تقديم واعتماد محدود إن خُول | صناديقه وسنداته | لا تعديل أرصدة؛ عجز الصندوق يحتاج موافقة |
| أمين المخزن | استلام وصرف وجرد | اعتماد مخزني | مخازنه والكميات | تكلفة مخفية افتراضيًا |
| المبيعات | عملاء وعروض وأوامر وفواتير | حسب سقف السعر والخصم | عملاؤه/فرعه | تجاوز الائتمان أو الخصم يحتاج موافقة مستقلة |
| المشتريات | موردون وطلبات وأوامر وفواتير | حسب المبلغ | موردون وعقود مخولة | تعديل بنك المورد يحتاج مراجعة ثنائية |
| الكاشير | بيع وقبض وردية | إتمام بيع ضمن حدود | ورديته | المرتجع وإلغاء السطر حسب الصلاحية |
| الموارد البشرية | موظفون ومدخلات رواتب | تجهيز المسير | ملفات موظفين مخولة | بيانات الرواتب منفصلة عن صلاحية المحاسب العامة |
| المدير المالي | موازنات واعتمادات | إقفال وفتح استثنائي | جميع البيانات المالية المصرح بها | سبب موثق للإجراءات الاستثنائية |
| المدقق | لا ينشئ حركات | لا يرحل | قراءة وطباعة بحسب التكليف | لا تعديل سجل التدقيق |

كل صلاحية = **عملية × شاشة × شركة/فرع × نطاق بطاقة × حد مبلغ**. الإخفاء في الواجهة ليس إنفاذًا للصلاحية. تصدير Excel أو طباعة كشف أو عرض التكلفة صلاحيات مستقلة.

## الفصل بين المهام

تعديل حساب بنك المورد → مراجعة شخص آخر → السماح بالسداد. إنشاء جرد → عد مستقل عند الاختلاف → اعتماد التسوية. إنشاء مستند → مراجع → معتمد وفق السقف. تعديل سياسة ضريبة أو تسلسل → موافقة وإصدار مؤرخ. إعادة فتح فترة → مدير مالي مخول + سبب + سجل قبل/بعد + إعادة المطابقات.

المنشأة الصغيرة قد تمنح أدوارًا متعددة للمستخدم؛ تظهر استثناءات الفصل في تقرير رقابي وتحتاج اعتماد سياسة صريح عند الإعداد.

## جودة وأداء مقترحان للقياس لاحقًا

- هدف أولي: 50 مستخدمًا متزامنًا، مليون سطر حركة سنويًا، 100 ألف صنف؛ أرقام تصميم افتراضية لا نتائج اختبار.
- الهدف: 95% من عمليات البحث أقل من ثانيتين؛ ترحيل فاتورة 100 سطر أقل من 3 ثوانٍ في بيئة مرجعية توثق قبل القياس. تقارير ثقيلة مهام خلفية.
- منع ضياع التعديل عبر رقم إصدار ومقارنة عند الحفظ. الترحيل يقفل موارد التخصيص والكمية حسب ترتيب ثابت ويتعامل مع التعارض.
- حفظ UTC للأحداث مع المنطقة الزمنية، وتواريخ العمل المحلية مستقلة.
- نسخ مشفر دوري مع اختبار استعادة؛ هدف أولي RPO ساعة وRTO أربع ساعات، قابلان للاعتماد حسب البنية.
- مراقبة فشل الترحيل، تأخر الإرسال الضريبي، فشل النسخ، تباطؤ التقارير، وتعارض أرصدة الدفاتر.
- تشفير الاتصال، كلمات مرور مجزأة بخوارزمية مناسبة، مصادقة إضافية للأدوار الحساسة، إدارة أسرار خارج السجلات، ومدة جلسة قابلة للضبط.
- لا تُنسخ بيانات إنتاج إلى بيئة تدريب دون إخفاء؛ جميع الأمثلة في الحزمة صناعية.

## نقل البيانات والأرصدة الافتتاحية

الترتيب: شركة وفترات ← عملات وأسعار ← شجرة حسابات ← مراكز ← أطراف ← مخازن ووحدات وأصناف ← أرصدة تفصيلية ← تسويات مطابقة ← اعتماد بدء التشغيل.

يستورد كل سطر برقم مصدر وبصمة ملف ودورة استيراد، مع معاينة الأخطاء قبل الالتزام. تحفظ خريطة أرقام النظام القديم إلى الجديد. لا تكرر حساب رقابة العملاء مرة من ميزان المراجعة ومرة من أرصدة العملاء؛ يرحل التفصيل ويُستبعد إجماليه من مسار الأستاذ أو يستخدم حساب ربط افتتاحي حتى تصفيره.

اختبارات البداية: العملاء = الرقابة؛ الموردون = الرقابة؛ تقييم المخزون = حساباته؛ صافي الأصول = التكلفة ناقص المجمع؛ الصناديق والبنوك = الأرصدة المعتمدة؛ إجمالي المدين = الدائن. لا يبدأ التشغيل مع فرق «مؤقت» غير مفسر.
